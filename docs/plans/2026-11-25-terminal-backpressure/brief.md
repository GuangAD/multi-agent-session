# 终端输出背压与渲染修复 · 设计说明

> 2026-11-25 | 状态:已批准 | 档位:完整
> 访谈与方案对比在 2026-11-24~25 的会话对话中完成并经用户逐项拍板,本 brief 只做固化记录。

## 1. 背景与问题

多开终端后,切回旧标签画面空白、要等约半分钟才显示;终端频繁冻结、不能滚动。经逐层取证定位四个根因:xterm beta 版的两处上游缺陷(隐藏时滚动位置被 NaN 毒化;渲染回调可自我排队形成单帧死循环)、主进程逐块转发 IPC 的事件风暴、渲染层无流量控制、隐藏终端照常解析渲染。问题在单终端时代不明显,多开并发后成为日常障碍,非修不可。

## 2. 目标 · 非目标 · 失败形态

**目标**

- 多开 3 个以上终端来回切换,不再出现「切回空白等半分钟」与整窗冻结
- 终端滚动任意时刻可用
- agent 持续大量输出时界面交互不掉帧
- 切回旧标签一帧内出画面,错过的输出秒级渐进补齐
- 关标签、agent 自退、强杀三场景的退出语义保持正常

**非目标**

- 不做 node-pty C++ 层 Job Object 树杀(挂账,见第 5 节)
- 不做 WebGL context 按需化(挂账:真实用到 16 个以上终端再做)
- 不做终端画面回放与输出日志(既有口径不变)
- 不基于 herdr-app 重置架构(已评估否决)
- 不改动 agent 状态 hook 通道与回填机制

**失败形态**

- 补丁进来了,多开切换仍偶发空白——NaN 防护不完整,白打
- 队列丢最旧的语义做错位置,可见画面缺内容
- 隐藏暂停解析弄瞎状态识别——违背 hook 通道不依赖终端缓冲的架构前提
- 合并转发把退出事件排到尾数据之前,会话结尾丢字
- 后台 fit 走了隐藏容器的零尺寸测量,把后台终端压成最小网格打到 agent

## 3. 选定方案

留在现有 Electron 架构内分七步修复:补丁层(照搬 Orca 对 xterm 与 node-pty 的既有 pnpm 补丁,重放即生效)+ 流控层(主进程时间窗合并转发、渲染层帧预算与在途上限双闸背压、隐藏终端只入队不消费、隐藏终端后台按假想尺寸重设网格)+ 恢复层(WebGL 降级后下次激活尝试重挂)。被否方案:

- 基于 herdr-app 重置——业务层全部重写、丢掉已验证资产,成本不成比例
- 运行时防护层(包装 xterm 私有 API)——被「直接照搬 Orca 根级补丁」取代:查证确认与 Orca 同机制同版本,重放零冲突
- 仅帧预算限流、不做在途上限——挡不住持续洪峰,喂入持续快于消化时队列仍无限涨
- node-pty C++ 层 Job Object——需要本地编译原生模块,收益是清理质量而非稳定性,挂账观察

## 4. 约束

- 技术栈与版本钉死:Electron + React 19 + @xterm/xterm 6.1.0-beta.336 + node-pty 1.1.0;不新增运行时依赖
- xterm 与 node-pty 版本必须与 Orca 快照一致,这是补丁重放零冲突的前提;升版本前须重新生成补丁
- 进程边界:Node 能力只在主进程,渲染层只走桥,契约先行
- ADR-0007:状态证据来自 agent hook 事件,不依赖终端缓冲——隐藏暂停解析的安全性前提
- ADR-0004:PTY 常驻 shell;退出事件语义 = shell 死亡
- ADR-0003:应用永不保存或改写对话内容,不做画面回放
- 每步独立提交、独立回滚;类型检查与全部既有单测绿加手动冒烟后才提交

## 5. 关键决策

- 整体走现有架构内修复(方案 A),不基于 herdr-app 重置 [你]
- xterm 修复照搬 Orca 根级补丁,经 pnpm 补丁机制重放;否决运行时防护层 [你]
- node-pty 补丁只取 JS 层;C++ Job Object 挂账,重启信号 = 僵尸进程频发 / 宿主进程堆积 / 要支持 Git Bash [你]
- 七步实施清单与验收口径按对话定稿执行:补丁层、合并转发、双闸背压、隐藏只缓冲、后台 fit、WebGL 重挂 [你]
- 接受后台 fit 对 ConPTY 下的 TUI 程序尽力而为的边界(shell 场景立竿见影) [你]
- node-pty 补丁的 C++ 段随重放进入源码但保持不编译,属已知无害状态 [我]
- 合并转发窗口取 16 毫秒或 64KB 先到先发;退出事件发出前先清空该会话缓冲保序 [我]
- 渲染层背压取双闸形态:每帧喂入预算、按写入回调计数的在途上限、队列内存上限、超限丢最旧 [我]
- 既有「先到先存」暂存袋与新队列合并为一套,注册前后同一条路 [我]
- WebGL 降级后标记,下次激活尝试重挂,失败保持 DOM 渲染 [我]

## 6. 未定项

| 未定的事 | 波及哪里 | 不定会怎样 |
|---|---|---|
| xterm 补丁附带的输入法与渲染段,与既有宽度表 provider 组合是否有行为差异 | 终端渲染冒烟 | 冒烟发现后单点评估,不影响整体结构 |

## 7. 验收标准

### 7.1 验收条目

1. 多开 3 个以上终端来回切换并让 agent 持续输出,不出现切回空白与整窗冻结
2. 终端滚动任意时刻可用
3. agent 狂输出时打字、切标签等交互不掉帧
4. 切回旧标签一帧内出画面,约一秒内渐进补齐错过的输出
5. 隐藏期间拉宽窗口,切回 shell 标签宽度立即正确
6. 关标签、agent 自退、点关闭强杀三场景,退出语义正常、无异常残留
7. 后台会话的 spinner 状态与等输入通知不受隐藏缓冲影响
8. 主题外观、emoji 宽度、终端滚轮行为不回归
9. 类型检查与全部既有单测绿

### 7.2 测试接缝

- 优先复用既有接缝:渲染层终端容器与外观应用的既有测试、主进程 PTY 注册表的既有测试、暂存袋上限既有用例
- 新开三个接缝,理由:转发现为直通、数据泵现为直灌、后台 fit 无稳定信号可依,均无可测点——
  - 主进程合并器:纯函数接缝,覆盖窗口合并、阈值提前清空、退出保序三组行为
  - 渲染层调度器:队列消费与背压,以假终端验证预算闸与在途闸
  - 窗口稳定门:resize 抖动合并与稳定信号,纯逻辑函数级(2026-11-25 切片期增补,登记于 plan.md 开发记录)
- 补丁层是第三方产物,不做单测,靠重放验证加实机冒烟
