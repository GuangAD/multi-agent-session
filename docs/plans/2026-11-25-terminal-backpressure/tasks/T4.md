# T4 渲染层数据泵双闸与隐藏只缓冲

> 依赖:无(单测);实机验收体验依赖 T1 已落地 | 对应:brief 第 2 节、spec 的 T4 覆盖标准

## 实现方式

**干什么**:重构渲染层数据泵为统一队列 + 双闸调度——帧预算限制喂入、写入回调限制在途,隐藏终端只入队不消费,切回渐进追平。

**输入**:bridge 的 `pty:data` 事件(注册前后同一条路);终端可见性变化。

**处理**

1. 新建调度器:每会话队列(字符串数组)+ 在途计数;`enqueue` 超限丢队首
2. `pump` 每帧由 use-terminal 驱动:可见会话按预算出队喂 `write(chunk, done)`,done 回来减在途
3. 在途达上限的会话本帧跳过,回调到达自动恢复
4. 隐藏会话跳过消费;`setVisible` 由 open/activate/close 接线维护
5. 既有 `pendingData` 并入:未注册会话同样入队,注册即开始消费,语义保持「先到先存、注册即放」

**失败与退出**:`done` 回调异常不计数修正——在途按投递计一次,投递即入账、回调只减一次;会话移除时队列与计数一并清理,无泄漏。

## 接口(伪代码)

落点:`src/renderer/src/components/terminal/terminal-write-scheduler.ts`(新文件)

```ts
type WriteSchedulerOptions = {
  write: (sessionId: SessionId, chunk: string, done: () => void) => void
  frameBudgetChars: number; inflightLimitChars: number; queueLimitChars: number
}
// 定义见 spec.md 数据结构节

createWriteScheduler(options: WriteSchedulerOptions): WriteScheduler
  // 用途:渲染层唯一数据出口,洪峰限速 + 隐藏缓冲,防主线程饱和
  // 怎么用:pump 由外部 RAF 每帧调一次;enqueue 可先于注册(未注册会话照常入队);同一会话投递未完成(done 未调)前该会话可能继续受预算闸约束
  // 出错时:done 未被调用导致在途虚高时,会话表现同在途闸停喂,不崩;remove 后该会话永不再喂
```

接线落点:`src/renderer/src/components/terminal/use-terminal.ts`(改造数据泵段)

```ts
ensureDataBus: onPtyData → scheduler.enqueue(sessionId, data)
openTerminal: 创建 write 包装(terminal.write + done 递减)→ setVisible(true);移除 pendingData 旁路(并入队列)
activateTerminal: setVisible(true)
closeTerminal: scheduler.remove(sessionId)
RAF 循环: 常驻,每帧 scheduler.pump()
```
