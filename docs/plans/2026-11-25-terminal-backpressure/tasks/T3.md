# T3 主进程合并转发

> 依赖:无 | 对应:brief 第 2 节、spec 的 T3 覆盖标准

## 实现方式

**干什么**:在注册表与渲染层之间插入每会话合并器,把每秒数千条数据事件压到每会话约 60 条,并保证退出事件不越过尾数据。

**输入**:注册表 `onData` 的会话字节块;`onExit` 的会话结束信号。

**处理**

1. 新建合并器:每会话一个缓冲串与一个定时句柄,窗口由 options 注入
2. `push`:入缓冲;首块起算窗口;单块或累计超阈值立即清空发出
3. `flushSession`:立即清空该会话缓冲并发出(供退出保序调用);无缓冲时无动作
4. 接线改造:`onData` 改为入合并器;`onExit` 先 `flushSession` 再发退出事件

**失败与退出**:合并器自身不产生错误路径;接线层投递失败沿用既有 `sendToRenderer` 的窗口存活判断;`destroy` 清全部定时器,测试收尾用。

```ts
type CoalescerOptions = { windowMs: number; maxChars: number; flush: (sessionId: SessionId, text: string) => void }
// 定义见 spec.md 数据结构节

createPtyDataCoalescer(options: CoalescerOptions): PtyDataCoalescer
  // 用途:把高频小数据块按会话合并成低频整块,降低 IPC 事件风暴
  // 怎么用:构造一次全程复用;push 可并发乱序跨会话调用;窗口定时器为每会话单槽,重复 push 只续期不叠加
  // 出错时:自身不抛错;flush 回调内的异常由接线层负责,缓冲已清空不会重发

接线落点:`src/main/ipc/pty.ts`(改造转发段)
  // onData 监听 → coalescer.push
  // onExit 监听 → coalescer.flushSession(sessionId) 后再 sendToRenderer(exit)
```

## 开发步骤

1. 写测试:同会话三块入缓冲、推进一个窗口,只发出一条合并串(期望来源:手算拼接结果)
2. 运行:`pnpm vitest run src/main/pty-data-coalescer.test.ts`;Expected: FAIL,`1 failed`,红因是模块尚不存在
3. 写最小实现(落点:`src/main/pty-data-coalescer.ts`)
4. 运行:`pnpm vitest run src/main/pty-data-coalescer.test.ts`;Expected: PASS,`1 passed`,且不是 0 条
5. 按 spec 覆盖矩阵逐条补齐用例 2-8(阈值提前、退出保序、多会话隔离、窗口续期、destroy 清理、空串边界),每条先红后绿
6. 改造接线(落点:`src/main/ipc/pty.ts`):onData 入合并器、onExit 先清空再发
7. 运行:`pnpm vitest run src/main/ipc/ 2>/dev/null; pnpm vitest run src/main -k "coalescer or pty"`;Expected: 相关模块全绿,条数 = 合并器用例 + 既有 pty 相关用例
8. 运行:`pnpm typecheck`;Expected: exit 0
9. 实机冒烟:开两个会话让 agent 输出,DevTools 确认 `pty:data` 频率降至每会话约 60 条/秒;终端里快速敲键回显仍即时;关标签时尾部输出完整、无丢字
10. 记录结果,交 controller 验证与提交
