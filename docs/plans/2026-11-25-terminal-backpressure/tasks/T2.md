# T2 node-pty JS 层补丁重放

> 依赖:无 | 对应:brief 第 2 节、spec 的 T1/T2 补丁覆盖标准

## 实现方式

**干什么**:引入 Orca 对 node-pty 1.1.0 的补丁,取其 JS 产物段(错误封堵、自退泄漏修复、加载重试)生效;C++ 段随重放进入源码但保持不编译。

**输入**:`.reference/orca-1.4.265/config/patches/node-pty@1.1.0.patch`(只读快照)、根 package.json。

**处理**

1. 补丁文件拷入仓库补丁目录
2. package.json 的 pnpm 段追加映射
3. `pnpm install` 触发重放
4. 重放验证 + 全量检查 + 三场景冒烟

**失败与退出**:重放冲突即停手报告;冒烟发现退出语义变化即停手,按回退协议升级——错误封堵改变了 exit 的触发路径,这是本任务唯一的行为风险点。

## 接口(伪代码)

不适用——本任务无新增代码接口。注意:补丁为 node-pty 增加了 JS 层不会主动暴露的原生导出(terminateJob 等),本项目不调用它们,不接桥。

## 开发步骤

1. 拷贝补丁:`.reference/orca-1.4.265/config/patches/node-pty@1.1.0.patch` → `config/patches/node-pty@1.1.0.patch`
2. package.json 的 pnpm 段追加 `"node-pty@1.1.0": "config/patches/node-pty@1.1.0.patch"`
3. 运行:`pnpm install`;Expected: 重放零冲突,exit 0
4. 验证 JS 段落地:`grep -c "ConPTY output relay exited" node_modules/node-pty/lib/windowsPtyAgent.js`;Expected: ≥ 1
5. 确认 C++ 段状态:`node_modules/node-pty/build/Release` 下无重新编译产物(重放只改源码文本,不触发编译);Expected: pty.exe / conpty 产物时间戳早于本次安装
6. 运行:`pnpm typecheck`;Expected: exit 0
7. 运行:`pnpm test`;Expected: 全部既有用例绿,条数与基线一致(`pty-registry.kill-tree.test.ts` 依赖真实 ConPTY 台架,本机不可达的既知豁免维持原样)
8. 实机冒烟:①agent 自退(终端里敲 exit)→ 标签正常收场;②点 × 关标签 → 无残留;③连开两个会话,令其中一个管道异常退出 → 另一个不受影响
9. 记录冒烟结果,交 controller 验证与提交
