# 侧栏会话行与项目行视觉整理 · 设计说明

> 2026-11-22 | 状态:草稿 | 档位:一页纸

## 1. 背景与问题

侧栏项目行和会话行的视觉元素偏多、行距偏挤。项目行的文件夹图标对层级表达没有帮助；会话行尾部常驻四个状态圆点，与行首信息争夺注意力，而 agent 正在工作时缺少一个显眼的指示；改名要移到行尾点铅笔图标，操作绕；会话行上下留白不够，看起来拥挤。

## 2. 目标 · 非目标 · 失败形态

**目标**

- 项目行不再显示文件夹图标，保留展开箭头与「+」「…」按钮
- 会话行徽标左侧在 agent 工作时显示旋转 loading 动画；会话行尾部状态点全部不再显示
- 会话行去掉铅笔图标，双击标题进入改名
- 会话行上下增加留白，视觉不再拥挤

**非目标**

- 不改运行状态枚举、状态引擎、IPC 契约、持久化数据
- 不改标签页区的「已退出」标记
- 不改删除按钮及其行为
- 不改单击会话打开/重开的行为
- 不改文件夹树面板与 Git 面板
- 不改 agent 徽标本身

**失败形态**

- 行尾点删了，但行首 working 动画没出现，工作时会话行无任何指示
- 双击改名与单击打开串扰：单击误触发改名，或双击时先打开会话再弹输入框
- 标签页已关闭的会话仍残留旋转动画
- 项目行的展开箭头或「+」「…」被误删，折叠/新建/导入入口丢失

## 3. 选定方案

纯渲染层调整：会话行组件按运行状态在徽标左侧渲染一个旋转动画，删除行尾状态点渲染与铅笔按钮，标题区加双击进入改名并用短延迟消歧单击，会话行容器增大上下 padding；项目行组件删除文件夹图标。不改任何状态语义与数据结构，loading 是 working 态的渲染层表达，不是新状态。

被否：把 loading 做成 `SessionRunState` 新枚举值并让状态引擎产出——穿透 shared 类型、IPC、fixture 与 store，成本高且语义无收益。行首与行尾同时显示 working 指示——重复表达。

## 4. 约束

- 渲染层永不 import main,一切经 ipc/bridge(AGENTS.md 工程边界)
- 运行状态唯一来源是主进程 `state:changed` 广播,渲染层不自行判定(ADR-0001 采样信号、既有 T5 口径)
- 会话行命名空间与既有交互保持一致:单击打开/重开、Esc 取消改名、Enter 提交、空名不提交
- 已有 lucide-react 图标集可用，不新增依赖
- 目录名用具体领域名,不设 utils/helpers(AGENTS.md)
- 单测与源码同目录,纯逻辑测试口径不变(AGENTS.md 执行纪律)

## 5. 关键决策

- 文件夹图标只删项目行那个，展开箭头与「+」「…」保留 [你]
- loading 仅渲染层表达 working 态，不进 `SessionRunState` 枚举与状态引擎 [你]
- loading 放在会话行徽标左侧（行首），行尾所有状态点删除 [你]
- loading 仅在 working 态显示旋转动画，其余态与未收到广播时不显示 [你]
- 改名改为双击标题触发，铅笔图标删除，删除按钮保留 [你]
- 会话行上下增加留白，列表项间距不动 [我]
- 单击/双击消歧采用短延迟判定，阈值由实施者按手感定 [我]
- loading 图标选型与动画样式由实施者在现有 lucide 图标集内决定 [我]

## 6. 未定项

无。

## 7. 验收标准

### 7.1 验收条目

- 项目行：无文件夹图标，展开箭头、「+」「…」均在且功能不变
- 会话行：agent 工作时徽标左侧显示旋转动画，行尾无状态点
- 会话行：非 working 态（等待输入/空闲/已退出）与无标签页会话，行首无动画、行尾无点
- 会话行：双击标题进入改名输入框，单击仍打开/重开会话，两者不串扰
- 会话行：Enter 提交改名、Esc 取消、空名不提交，与既有行为一致
- 会话行：上下留白比改前明显增加
- 全量测试绿、typecheck 通过

### 7.2 测试接缝

- 无新自动化接缝：本特性为纯渲染层视觉与交互调整，项目测试范围为纯逻辑，组件级交互无自动化接缝，预登记 waiver
- 双击/单击消歧与视觉效果靠手动冒烟验证
