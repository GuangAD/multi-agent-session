# T1 hook 状态引擎与事件契约

> 依赖:无 | 对应:brief 第 3 节引擎半边、spec 数据结构/模块划分(agent-state 段)、覆盖标准 1/4

## 实现方式

`shared/agents.ts` 的 `AgentStateRules` 破坏性重构:删除 `degraded` / `title` / `screen` / `bytes` / `idleQuietMs`,改为 `hooks: { working: string[]; waiting: string[]; idle: string[] }`(事件名 → 目标态映射,事件名 = 各 CLI 原生事件名)。同文件 `AgentDefinition` 增可选 `hooks?: HookInstallDecl`(注入声明:`kind` + 各事件的注册信息形状,T1 只落类型,T3 消费)——shared 契约一轮改完,避免两轮破坏。

新引擎接缝 `src/main/agent-state/hook-tracker.ts`:`createHookTracker(def, opts?)` 返回 `{ onHookEvent(event), onExit(), state(), onChange(cb) }`。语义:事件命中 def.state.hooks 某槽 → 目标态**事实直落**(不经 requestState 去抖,沿 onExit 的 publish 模式);`publish` 内 next===state 早退 = 同态幂等;创建即 seed idle(广播,沿现 trackerForPty 的 `{seed}` 语义);`exited` 终态后一切输入忽略;未知事件(不挂任何槽)静默忽略。

`ipc/state.ts` 最小适配(保编译绿,完整重写在 T2):tracker 表与 PTY 生命周期挂接保留,喂食入口换成 `onHookEvent`(本任务阶段无事件源,状态恒 seed idle 的过渡态可接受);title/snapshot 上行 handler 暂留壳(T4 删契约)。

五插件 `plugin.ts` 的 state 段按 spec 映射表改写(旧规则删除);`state-parser.ts`、五家读屏 fixture、`state-parser.test.ts` 删除;新 fixture 落 `__fixtures__/*.hook-fixture.ts`(事件名序列)+ `hook-tracker.test.ts` 回放。

## 接口(伪代码)

落点:`src/main/agent-state/hook-tracker.ts`

```ts
export function createHookTracker(def: AgentDefinition, opts?: { now?: () => number }): {
  onHookEvent(event: string): void   // 命中槽 → publish 直落;未知事件忽略
  onExit(): void                     // 终态,clearTimers 不需要(无定时器),publish('exited')
  state(): SessionRunState
  onChange(cb: (s: SessionRunState) => void): void
}
// def.state.hooks 查表顺序不敏感(每事件只可能挂一槽,声明期约束,运行期先命中先判)
```

落点:`src/shared/agents.ts`

```ts
interface AgentStateRules { hooks: { working: string[]; waiting: string[]; idle: string[] } }
interface HookInstallDecl { kind: 'claude-settings' | 'codex-json' | 'antigravity-json' | 'pi-extension' | 'kimi-toml' /* 注册信息形状 T3 定 */ }
interface AgentDefinition { /* ... */ state: AgentStateRules; hooks?: HookInstallDecl }
```
