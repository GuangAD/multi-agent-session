## 实现方式

`src/main/agent-hooks/forwarder-script.ts`:纯函数 `generateForwarderScript(): string` 产出转发脚本文本——头部版本注释;解析 `--agent <id> --event <Name>` 参数;读 `SOLOPORT_HOOK_PORT` / `SOLOPORT_SESSION_ID` / `SOLOPORT_HOOK_TOKEN`;任一缺失 `process.exit(0)` 早退;聚合 stdin(payload 原样转交,不解析);`fetch(http://127.0.0.1:<port>/hook)` POST,JSON body `{ agent, sessionId, event, payload }`,header 带 token;任何异常静默;**恒 exit 0**(fail-open)。脚本落盘 `userData/hook-scripts/forwarder.mjs`(T3 的 injector 调用写盘;本任务先落生成与写盘函数)。`buildHookCommand(nodePath, agent, event)` 产出配置里的命令串(`"<node>" "<script>" --agent <id> --event <Name>`)。

`src/main/agent-hooks/receiver.ts`:`listen(): { port, token, stop() }`——http.createServer 绑 127.0.0.1,listen(0) 取随机端口;token = 每次应用启动随机生成;仅接受 POST /hook;校验 header token、body `{agent, sessionId, event}` 非空、body ≤64KB;路由判定抽纯函数 `resolveHookTarget`(见接口),命中 → 喂对应 tracker.onHookEvent;未命中/坏请求静默 4xx,不影响 CLI。

`ipc/state.ts` 重写:持有 receiver;事件 → `trackerForPty` 表查会话 → `onHookEvent`;tracker 创建(seed)/退出摘除沿现有编排不变;maybeNotify(等输入通知)接线保留。

`ipc/pty.ts` 组合点:spawn 的 env 段追加 `SOLOPORT_SESSION_ID` / `SOLOPORT_HOOK_PORT` / `SOLOPORT_HOOK_TOKEN`(receiver 未启动时的防御:缺端口则不注入,spawn 照常)。

**env 继承探针(实施期第一验证项)**:claude 与 pi 各配一个临时 hook(项目级),断言脚本能把 `SOLOPORT_SESSION_ID` 原样 POST 回来;结论进开发记录;探针为临时件,复现后移除(DBG 纪律)。

## 接口(伪代码)

落点:`src/main/agent-hooks/receiver.ts`

```ts
export function resolveHookTarget(p: {
  token: string | undefined      // POST header
  expectedToken: string          // receiver 持有
  sessionId: string | undefined  // body
  agent: string | undefined      // body
  event: string | undefined      // body
  activeSessionIds: SessionId[]  // ptyRegistry 活跃表
}): SessionId | null
  // 任一字段缺失/token 不匹配/sessionId 不在活跃表 → null(调用方静默 4xx)
```

```ts
export function listen(deps: { onEvent: (sessionId: SessionId, event: string) => void }): {
  port: number; token: string; stop(): void
}
```
