# T5 状态识别三源引擎

> 依赖:T4 | 对应:brief 第 2 节目标 3、spec 覆盖标准「接缝 stateTracker」

## 实现方式

主进程 `state-parser` 提供每会话一个追踪器:输入三源事件——标题(xterm onTitleChange 经 IPC 上行)、屏幕快照(渲染层对常驻实例 `buffer.active` 节流序列化的可见行文本)、字节缓冲(环形缓冲保留最近 64KB,跨 chunk 拼接后子串匹配)、退出事件;输出状态经 `state:changed` 广播。判定顺序即证据分级:退出 > waiting 地标 > working 信号 > 标题规则 > 静默超时 idle;状态变更去抖(同态 300ms 内不重复广播),exited 为终态。kimi 走降级(有输出=working、静默=idle)。校准流程:用 T3 采样开关对 5 家各采真实输出(启动/干活/提问/退出各一段),脱敏后入 `__fixtures__`,规则按 Orca 对应 json 的信号要点填写;样本不足的先用构造样本,采样后替换。渲染层 run-state-slice 消费状态,会话行渲染状态点。
