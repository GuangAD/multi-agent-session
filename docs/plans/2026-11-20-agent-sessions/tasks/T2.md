# T2 agent 配置层与安装检测

> 依赖:T1 | 对应:brief 第 2 节目标 1、spec 覆盖标准「接缝 agentRegistry / resolveCommandPath」

## 实现方式

定义注册表收拢 5 个 agent 定义(状态规则、扫描与续接挂载点本任务先留接口,实现分别在 T5–T8 填充);PATH 探测整文件移植 Orca 的 command-path-resolver 及其配套(node-cli-command-resolution、map-with-concurrency),剥掉 worker 目录读取。安装检测在主进程完成,`agents:list` 一次返回全部定义与安装状态;渲染层新建会话选择器消费之。五家命令名沿用 Orca catalog:claude / codex / agy / pi / kimi(别名 kimi-code),M2 冒烟时在本机实测,检测不到的在定义文件覆盖命令(遗留项承接)。

## 开发步骤

1. 移植:从 `.reference/orca-1.4.265/src/main/ipc/command-path/command-path-resolver.ts` 整文件搬入,补文件头来源标注;配套搬 `getExecutableNames` 与 map-with-concurrency 两个纯函数文件
2. 写测试:resolver 五条用例(见测试规格;期望来源:构造的假 PATH 环境,手算)
3. 运行:`pnpm vitest run src/main/command-path/command-path-resolver.test.ts`;Expected: FAIL,`5 failed`,红因是移植件尚未适配本仓导出
4. 完成移植适配;运行同上;Expected: PASS,`5 passed`
5. 写测试:registry 五条用例(期望来源:brief 第 5 节固定清单,手算)
6. 运行:`pnpm vitest run src/main/agents/agent-registry.test.ts`;Expected: FAIL,`5 failed`
7. 写五份定义文件与注册表(状态规则初版照抄 Orca 对应 json 的信号要点:title 规则给 claude/pi,screen 地标给 codex/antigravity,kimi 先 degraded:true;扫描/续接挂载留空位)
8. 运行:同步骤 6;Expected: PASS,`5 passed`
9. 接线:`agents:list` IPC + NewSessionMenu 渲染清单与安装状态
10. 运行:`pnpm typecheck`;Expected: PASS;`pnpm vitest run`;Expected: `15 passed`(T1 的 5 条 + 本任务 10 条)
11. 手动冒烟(交用户):本机实测 5 命令检测状态;pi/agy 异常则在定义文件覆盖

## 测试规格

### 接缝 agentRegistry(模块行为)
固定清单与别名归一,直接调用,不经 IPC。

| # | 输入 | 期望 | 期望值来源 |
|---|---|---|---|
| 1 | 依次取 claude/codex/antigravity/pi/kimi | 各返回对应定义,id 一致 | brief 第 5 节 |
| 2 | getById('unknown') | undefined,不抛错 | 约定 |
| 3 | getById('kimi-code') | 返回 kimi 定义 | brief 第 5 节 |
| 4 | list() | 5 条,顺序与注册一致 | 手算 |
| 5 | register 注册重复 claude | 抛错 | 约定 |

### 接缝 resolveCommandPath(模块行为)
注入假 pathEnv/exts,不依赖真实环境。

| # | 输入 | 期望 | 期望值来源 |
|---|---|---|---|
| 6 | PATH 含命中目录 | 返回该命令绝对路径 | 手算 |
| 7 | PATH 无命中 | null | 约定 |
| 8 | 引号目录 `"C:\a b"` | 剥引号后命中 | 构造反例 |
| 9 | PATHEXT 大小写混合 | .EXE 与 .exe 等价命中 | 手算 |
| 10 | PATH 含不存在目录 | 跳过,返回 null 不崩 | 构造反例 |
