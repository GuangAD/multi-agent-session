# T7 会话导入:pi/kimi/antigravity 适配

> 依赖:T6 | 对应:brief 第 2 节目标 2、spec 覆盖标准「接缝 scanPi / scanKimi / scanAntigravity」

## 实现方式

三家适配器挂进各自定义文件的 scan 位,复用 T6 的 runImport 框架。pi:从 `~/.pi` 会话目录解析 transcript(id/cwd/title/转录路径,转录路径必须保留供续接);kimi:目录布局推导 + `state.json` 与 `session_index.jsonl` 双源,会话 id 保留 `session_` 前缀;antigravity:history 文件 + WorkspaceURIs 关联,无 cwd 字段的会话用首条 prompt-hash 与项目目录关联(实现顺序最后,方案取 Orca 扫描器裁剪)。三家的存储路径本机实测核对(遗留项承接,核对结论登记开发记录),实测不到路径的用户记录为「本机未装,导入返回空」。

## 接口(伪代码)

落点:`src/main/session-store/session-import/{pi,kimi,antigravity}.ts`(移植裁剪,文件头标注来源)

```ts
scanPi(projectPath: string): Promise<ImportCandidate[]>
scanKimi(projectPath: string): Promise<ImportCandidate[]>     // id 必须保留 session_ 前缀
scanAntigravity(projectPath: string): Promise<ImportCandidate[]>
  // 调用形状:定位存储目录 → 逐文件流式解析 → 产出候选;坏文件跳过不抛错
```

## 开发步骤

1. 本机核对三家存储路径(交用户配合);结论登记开发记录
2. 取脱敏真实样本入 `__fixtures__/`(pi/kimi/antigravity 各 1–2 份;本机没有的 agent 用 Orca 仓库自带 fixture 改造)
3. 写测试:五条用例(期望来源:fixture 实际内容 + Orca 扫描器测试的 fixture 工厂改造)
4. 运行:`pnpm vitest run src/main/session-store/session-import/`;Expected: FAIL,`5 failed`
5. 实现三家适配(pi → kimi → antigravity 顺序);运行同上;Expected: PASS,`5 passed`
6. 运行:`pnpm typecheck`;Expected: PASS;`pnpm vitest run`;Expected: `55 passed`(累计 50 + 5)
7. 手动冒烟(交用户):三家各对一个有历史会话的项目导入,列表出现、点击拉起正常
