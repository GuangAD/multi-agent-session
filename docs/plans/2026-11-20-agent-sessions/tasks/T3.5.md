# T3.5 shell 底座改造(ADR-0004,变更任务)

> 依赖:T3 | 对应:ADR-0004;T3 冒烟两项发现(退出后不可再交互、TUI 接管滚轮)的修复载体

## 实现方式

PTY 从「直接跑 agent CLI」改为「跑常驻 shell(Windows 首发 cmd),agent 由应用在 shell 内启动」:spawn 的 file 为 `ComSpec`(默认 cmd.exe),cwd=项目目录;shell 就绪后向其写入 agent 启动命令行(经 resolveCommandPath 解析的绝对路径,统一双引号包裹)并回车。CLI 退出(正常或崩溃)后回到 shell 提示符,标签页保留、终端可继续交互;`pty:exit` 语义收窄为「PTY(shell)退出」,即仅用户在 shell 里敲 exit 或 shell 崩溃时触发。滚动兜底:容器 wheel 事件在 Shift 按下或 alternate buffer 状态下强制本地滚动(`terminal.scrollLines`),绕过 TUI 应用对滚轮的接管。

## 约束与口径

- `pty:exit` 语义变更已入 spec(ADR-0004):agent CLI 退出不触发 pty:exit,由 T5 状态引擎按信号判断;渲染层 runState 保持「PTY 生命周期」语义(shell 活 = running)
- 注入时机:cmd 无 banner,spawn 后立即写入通常可靠;若冒烟实测丢首字符,改为等待首帧 data 再注入(实现内自行决策,报告说明)
- 注入行的回显(cmd 会把输入行回显)即用户看到的「命令行」,不需要额外处理
- shell 选择:Windows 首发 `process.env.ComSpec ?? 'cmd.exe'`;不做 POSIX shell 适配(非首发平台)
- samplingTap/killAll/closeTerminal/事件转发均不变(仍是 PTY 层语义)
- T8 挂点:重开会话 = 新 shell PTY + 注入 resume 命令——T3.5 只保证「注入命令行」机制可用,resume 参数构造归 T8
