# T6 会话导入:框架与 claude/codex

> 依赖:T4 | 对应:brief 第 2 节目标 2、spec 覆盖标准「接缝 path-match/runImport、scanClaude、scanCodex」

## 实现方式

导入框架 `runImport`:按 agent 定义取扫描器 → 解析出候选会话(元数据)→ `matchProjectDir` 按 cwd 归一化匹配项目 → 与现有记录按 (agentId, externalSessionId) 去重 → 命中忽略清单的跳过 → 其余入库(origin=imported,记 externalTitle 与 activityAt)。claude 适配整文件移植目录编码模块(非字母数字→`-`、Windows 大小写、长路径 200 字符 + hash 桶),jsonl 解析裁剪;codex 适配裁剪解析器、硬链接去重与 .zst 变体处理。fixture 用本机真实会话文件脱敏后入库。渲染层项目会话区加「导入」按钮(选 agent → 跑导入 → 结果提示),列表按 activityAt 倒序,超一屏折叠。

## 开发步骤

1. 取真实样本(交用户配合):从本机 `~/.claude/projects` 取 2–3 个会话 jsonl、`~/.codex/sessions` 取 1–2 个 rollout,脱敏(替换敏感字符串)后入 `__fixtures__/`;样本清单登记开发记录
2. 写测试:path-match/runImport 五条 + scanClaude 五条(期望来源:fixture 实际内容手算 + 构造反例)
3. 运行:`pnpm vitest run src/main/session-store/session-import/`;Expected: FAIL,`10 failed`
4. 实现 path-match、runImport、claude 适配(编码模块整文件搬);运行同上;Expected: PASS,`10 passed`
5. 写测试:scanCodex 五条;运行;Expected: FAIL,`5 failed`
6. 实现 codex 适配(裁剪 Orca 解析器/去重/变体逻辑);运行;Expected: PASS,`15 passed`
7. 接线:`sessions:import` IPC + 导入按钮 + activityAt 排序 + 折叠
8. 运行:`pnpm typecheck`;Expected: PASS;`pnpm vitest run`;Expected: `50 passed`(累计 35 + 15)
9. 手动冒烟(交用户):对装 claude 的项目导入 → 历史会话出现;点击拉起与新建一致;重复导入不重复;删除该会话后再次导入不再出现;确认 agent 存储未被改动
