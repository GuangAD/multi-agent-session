# Agent Sessions · 设计说明

> 2026-11-20 | 状态:已批准 | 档位:完整

## 1. 背景与问题

用户同时在多个项目目录里使用多个 AI 编程 agent CLI。会话散落在各 agent 自己的管理体系里:开会话要手动进目录敲命令,历史会话要到 CLI 里翻找,多个任务并行时无法一眼看出哪个在干活、哪个在等输入。需要一个轻量桌面应用:以项目为单位组织会话,一键拉起对应 agent,导入历史会话,并实时显示运行状态。

## 2. 目标 · 非目标 · 失败形态

**目标**

- 添加项目目录后可新建会话(从 5 个 agent 清单中选择),在应用内终端直接与 agent 交互
- 会话列表持久化,重启不丢;自建会话重开自动续接对话;可从 agent 存储导入属于当前项目的历史会话
- 后台会话显示运行状态点(干活/等输入/空闲/退出),多任务并行时一眼识别谁在等输入
- 文件浏览(只读)与 Git 基本操作(状态、差异、暂存、提交、切分支)
- 深浅主题手动切换,默认跟随系统;左栏与右栏均可隐藏收起;界面文案中文
- Windows 打包产物可安装启动

**非目标**(第一版)

- 清单 5 个之外的 agent(扩展方式 = 新增一个定义文件)
- 自由命令输入
- PTY 级终端画面回放
- 非匹配目录的历史会话导入
- i18n、自动更新、远程/SSH、多窗口、插件系统
- hook 通道状态上报(整体移出第一版,列为将来可选)
- push/pull/rebase 等远端 Git 操作
- 用户级输出日志与对话查看器(历史由 agent 存储负责)
- 「同一对话开多个窗口」的 fork 能力

**失败形态**

- 状态点永远显示「干活」,用户分辨不出谁在等输入——多任务场景失效
- 导入或续接时拉起了别的项目的对话——串线
- 关闭应用后留下孤儿 agent 进程继续烧 token
- 删除会话后 agent 存储被连带破坏——误删真实对话数据

## 3. 选定方案

Electron 单窗口单进程桌面应用:主进程独占全部 Node 能力,渲染层纯 UI,进程间走类型化契约桥;agent 接入用配置驱动的定义表,新增 agent 零框架改动;状态识别走「标题事件 + 屏幕快照 + 字节流缓冲」三源;终端容器用每会话常驻 xterm 实例;持久化用应用数据目录的单个 store 文件整文件原子写。被否方案:

- 照搬 Orca 的 daemon + execution-host 架构——为多窗口/远程设计,我们没有这些需求,代价是数万行基建
- hook 通道做状态上报——约 2.3 万行子系统、侵入用户全局配置、多会话并发下清理语义不成立
- serialize 重放式终端容器——为「画面与实例分离」的重连场景设计,单窗口不需要
- 自建输出日志/对话存储——历史已由 agent 存储负责,重复存储无收益

## 4. 约束

逐条抄自项目既有约定(AGENTS.md / PLAN.md):

- src/main/ 是全部 Node 能力唯一所在地;渲染层永不 import main,一切经 bridge;shared 是进程间契约唯一来源;preload 是唯一桥
- 目录名用具体领域名,不设 utils/helpers/common;单测与源码同目录
- 移植 Orca 代码文件头标注来源(MIT),保留 Why 注释;移植深度三档按附录 A 执行
- 状态识别用自研三源引擎,不搬 Orca 规则原文,但继承其纪律(标题优先、地标匹配、安静门槛、证据分级、why 字段、正反样本配对)
- 技术栈:Electron + electron-vite + TypeScript strict;React 19 + Zustand + Tailwind CSS 4;node-pty + @xterm/xterm + addon-fit;simple-git;vitest
- 每个里程碑 tsc --noEmit + vitest + 手动冒烟通过后,经用户确认再 commit;commit 中文带前缀
- 不推送远端、不发布
- Windows 为首发平台;node-pty 编译需 VS Build Tools + Python 3

- 5 个 agent 固定清单(claude/codex/agy/pi/kimi),配置驱动 [你]

- kimi 降级预案:最坏只做「有输出=干活、退出=退出」,等输入并入相邻态 [你]
- 采样落盘开关随 PTY 注册表一起实现,M3 直接用 [你]
- 回填 externalSessionId 用「同 agent + 项目单待回填」简单规则,指纹匹配后置为增强 [你]
- 同一会话禁止双开,不做 fork 分叉 [你]
- 终端容器常驻实例,不做 serialize 重放 [你]

- 不做用户级输出日志与对话查看器,历史归 agent 存储 [你]
- 职责边界:运行保持归应用、回显归 CLI、内容归 agent 存储、关闭后历史归 resume [你]
- 删除会话只删应用记录 + 忽略清单防导入扫回;重命名只改应用侧显示名,agent 侧原名与对话 id 常驻可查 [你]
- 深浅主题手动切换,默认跟随系统,参考 Orca [你]
- 左栏与右栏均可隐藏收起 [你]

## 7. 验收标准

### 7.1 验收条目

- 开发模式启动出三栏空窗口;添加目录后重启,列表仍在
- 对 5 个 agent 各新建会话并能交互;关闭后重开不丢记录;自建会话重开自动续接对话内容
- 对装有 claude 的项目执行导入,历史会话出现在列表;点击拉起行为与新建一致;重复导入不重复
- 各 agent 运行中/等输入时状态点正确切换(kimi 允许降级精度)
- 文件树可展开,点击只读查看,大文件截断提示
- 改文件出差异、按文件暂存提交、切本地分支
- 打包产物可安装启动
- 深浅切换生效;左栏右栏收起展开正常
- 删除会话后记录消失、agent 数据完好、再次导入不再出现

### 7.2 测试接缝

- 现有接缝:无(新项目)
- 新开接缝:store 持久化读写(原子写)、agent 注册表与安装检测、状态解析器(五 agent 正/反样本回放)、会话扫描器(脱敏真实样本回放 + 目录匹配)、文件树忽略规则、git 状态解析
- 开新接缝的理由:这些是纯逻辑层,输入输出确定;解析类必须用 fixture 回放防回归(真实 agent 输出样本),不能用在线服务测试
