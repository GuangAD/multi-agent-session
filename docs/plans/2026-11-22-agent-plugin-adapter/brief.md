# agent 插件化适配层 · 设计说明

> 2026-11-22 | 状态:已批准 | 档位:完整

## 1. 背景与问题

应用已接入五个 agent CLI,但接入点并不「插件化」。现状下新增一个 agent 需要改动至少四处核心代码:共享类型中封闭的 agent id 联合类型、渲染层硬编码的图标组件映射与品牌色映射、核心注册表里的手工 import 与逐个登记、以及住在导入域里的会话扫描器——最后这条正是 AGENTS.md 工程边界里记录的「领域横向依赖双向例外」的成因。

结果是:接入成本随 agent 数量线性上升;核心代码被 agent 清单反复穿透;主进程与渲染层都「认识」每一个具体 agent;两个本应单向的领域互相纠缠。

## 2. 目标 · 非目标 · 失败形态

**目标**

- 新增一个 agent = 新增一个自包含插件包 + 插件清单一行登记,不再改动任何核心文件
- 插件能力面收敛为:必选五项声明(身份元数据、启动命令、状态识别规则、品牌图标、品牌色)+ 可选两项行为(会话导入扫描、续接参数)
- 「导入框架 ←→ 定义」的双向依赖例外消灭:扫描器随插件走,导入域只保留通用编排与扫描 SDK
- 渲染层改为载荷驱动:图标与品牌色随 agents:list 载荷传输,未知 agent 走通用兜底
- 迁移全程行为零变化:现有五个 agent 的状态点判定、导入候选、续接参数与迁移前完全一致

**非目标**

- 运行时外部插件(npm 包 / 独立目录动态加载)不做——本特性交付仓内静态插件形态,未来需要时只需开放注册方式
- 插件自定义启动参数与环境变量不做
- 插件设置页、插件间依赖、插件生态与对外发布不做
- 状态识别规则保持声明式数据,不开放自定义解析函数

**失败形态**

- 目录搬家式重构:迁移完成后注册仍要改多处、或渲染层仍按 id 查硬编码表——插件化名存实亡
- 迁移引入行为变化:状态点判定、导入候选、续接参数与迁移前不一致(fixture 回放是判据,必须全绿且逐字对齐)
- 未知 agent 使渲染层崩溃:id 开放后,载荷中出现未登记图标/配色的 agent 时必须兜底渲染而不是抛错

## 3. 选定方案

仓内静态插件 + 显式注册。每个 agent 一个自包含插件包(声明式数据 + 可选行为函数 + 随包 fixture 回放测试),在插件清单登记一行;框架侧收敛为注册表、通用导入框架与扫描 SDK、通用状态引擎,渲染层由载荷驱动并带兜底。

被否:

- 运行时外部插件——不可信代码进主进程需要沙箱与 API 版本化,asar 打包要为外部目录开洞,复杂度翻数倍且当前没有真实需求;未来开放只需替换注册方式,插件包结构不变
- 目录扫描自动发现——动态 import 在打包器下要绕路,插件失去编译期类型检查,收益仅是省一行登记

## 4. 约束(逐条抄自项目既有约定)

- 渲染层永不 import main,一切经 ipc/bridge(AGENTS.md 工程边界)
- agents:list 出站必须剥离函数:Electron IPC 结构化克隆支持 RegExp、不支持函数(shared/agents.ts 顶部既有注释)
- 状态识别不用 hook 通道,走采样信号(ADR-0001)——插件状态规则仍是采样信号的数据声明,引擎零改动
- 删除会话不登记忽略清单,再次导入直接重新入库(ADR-0005)——扫描器迁移不改变该语义
- 单测与源码同目录;状态解析器与会话扫描器用 fixture 回放防回归(AGENTS.md 执行纪律)——fixture 随扫描器迁入插件包
- 目录名用具体领域名,不设 utils/helpers(AGENTS.md)
- 领域横向依赖的唯一例外(AGENTS.md 工程边界现行条目)——本特性完成后该例外应具备删除条件,条目更新在收尾执行

## 5. 关键决策

- 插件形态:仓内静态插件;运行时外部插件不做 [你]
- 注册方式:插件清单一行显式登记;目录扫描自动发现不做 [你]
- 能力面:必选五项(身份元数据、启动命令、状态识别规则、品牌图标、品牌色)+ 可选两项(会话导入扫描、续接参数) [你]
- 状态识别规则保持声明式数据形态,不开放自定义解析函数 [你]
- 品牌图标以 SVG 字符串随 IPC 载荷传输,渲染层内联渲染 [你]
- 品牌色为定义中的固定色字符串,不随主题翻转(沿用 agent 图标定稿方案) [我]
- agent id 从封闭联合类型开放为字符串;现有五个 id 保留常量供测试与兜底逻辑引用 [我]
- 插件包自包含:声明数据、扫描器、fixture 回放测试同住;通用导入编排、候选模型、路径与 home 目录工具收编为扫描 SDK 归导入框架 [我]
- 渲染层对未知 agent 走兜底图标与中性配色,不抛错 [我]
- 现 AgentDefinition 的首字母 icon 字段删除(渲染层已改品牌 SVG 渲染,该字段无持久化与外部消费) [我]
- agents:list 出站剥离函数的现状逻辑沿用;载荷新增图标字符串与品牌色字段(均为可克隆类型) [我]

## 6. 未定项

无——方向性问题在访谈中清零;载荷字段命名、SDK 函数切面等属规格层细节。

## 7. 验收标准

### 7.1 验收条目

- 新增一个验收用假 agent 插件(不进真实清单,仅验收存在):只新增插件包 + 清单一行后,应用 agent 列表出现该 agent,安装探测按其命令生效,状态点按其规则判定
- 现有五个 agent 行为零变化:状态识别 fixture 回放全绿;导入扫描候选与迁移前一致(各自 fixture 全绿);续接参数不变
- 依赖方向达标:导入框架不再 import 任何具体 agent 的扫描器;agents 域不再 import 导入域的具体扫描器(双向例外具备删除条件)
- 渲染层:五个 agent 按「载荷携带的品牌色 + SVG」渲染;载荷含未知 agent 时以兜底图标 + 中性色渲染,不崩
- 全量测试绿,typecheck 通过

### 7.2 测试接缝

- 状态识别 fixture 回放(现有接缝,零改动随迁)
- 扫描器 fixture 回放(现有接缝,随扫描器迁入插件包)
- 注册表语义:重复注册抛错、别名归一、清单副本(现有接缝,行为不变)
- 新接缝:插件清单装载(登记/去重/导出)与 agents:list 载荷形状(新增图标字符串、品牌色、安装状态)
- 状态引擎、PTY、存储、通知:零新接缝

## 8. 授权项

- 插件包与扫描 SDK 的文件级落点与函数切面
- IPC 载荷的字段命名
- 渲染层未知 agent 兜底图标的具体形态
- fixture 迁移后的目录组织细节
- 渲染层现有品牌图标组件文件的去留与整合方式(被载荷渲染取代的部分)
