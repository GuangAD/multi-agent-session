## 1. 背景与问题

用户唯一的外观操作是标题栏按钮循环切换浅色/深色/跟随系统,没有设置界面。终端配色、字体、界面色系都不可调:终端字体写死为一串回退链,界面颜色写死在各组件里。`shell` 与回滚行数两项已有设置也从未有过界面入口。

## 2. 目标 · 非目标 · 失败形态

**目标**

- 新增设置对话框,MoreMenu 入口,分「外观」「通用」两区。
- 界面主题与终端配色主题各一个下拉,单槽直选(不区分深浅、不跟随系统)。
- 终端配色主题全量移植 Orca 内置 22 套(深 13、浅 9),平铺成一个下拉。
- 界面主题内置 10 套(用户选定,见第 5 节),前提是界面颜色收敛为语义 token。
- 终端外观六项可调:字体族、字号、字重、行高、光标样式、光标闪烁。
- 外观区顶部有终端样式预览块,改动即时反映(主题已单槽,预览不带深浅切换钮)。
- 通用区可设默认 Shell 与回滚行数,这两项首次有界面。
- 全部改动即时生效、即时落盘;度量类变更作用于全部已开终端。

**非目标**

- 不做自定义主题编辑与用户导入(Ghostty/kitty/Warp 格式)。
- 不做终端主题逐色微调。
- 不做字体连字。
- 不做界面取色器自定义。
- 不做 Match Terminal(界面跟随终端背景)。
- 不做窗口材质、侧栏色调、背景图/视频。
- 不做滚动灵敏度、GPU 加速、内边距、不透明度等其余 Orca 外观项。
- 不做按项目覆盖设置,设置全局一份。

**失败形态**

- 对话框里改了字体,已开终端没变化或出现右侧空白带——有设置但没生效。
- 预览块与真实终端两副面孔——预览骗人。
- 旧数据打开报错或设置丢失——兼容失败。
- 切换主题后个别界面块颜色不变——token 化漏网,半深半浅。

## 3. 选定方案

对齐 Orca 的分层:主题即命名配色数据,界面与终端各自维护深浅两个槽。设置只存「选了哪套」,渲染时按当前深浅态解析出实际主题。界面颜色先收敛为语义 token 层再由主题套色;终端字体等度量项走终端配置单一来源,变更即时对全部终端生效。

被否的路线:

- 色相式单选(一套主题深浅通吃):用户明确选了双槽。
- 只做终端主题、界面不动:用户要界面主题,token 化绕不开。
- 字体纯文本输入(Orca 原样):用户选下拉预置,防错字体。
- 系统已装字体枚举补全(Orca 的做法):需主进程新增字体枚举通道,超出本轮范围。

## 4. 约束

逐条抄自项目既有约定:

- 字体族/字号/字重/加粗字重必须作为终端配置项传入或运行时更新,不得只改 CSS;canvas 测量与 DOM 渲染必须同一套字体度量(`docs/issues/2026-11-21-terminal-rendering.md` 七)。
- 度量类配置变更后必须对所有终端 refit,并经既有 resize 链路同步 PTY 网格(同上)。
- 颜色类配置可运行时更新,不必重建终端;回滚行数沿用「变化即重建实例」的既有语义(同上)。
- 渲染层永不 import 主进程,一切经 IPC 桥;设置由主进程持久化(AGENTS.md 工程边界)。
- 深色走 Tailwind class 策略;「谁把 dark 类写上 html」保持只有一处(现 `theme.ts` 职责),新机制扩展不得破坏。
- 终端布局层与滚动条样式已有 Orca 移植文件,不得绕开其结构另起炉灶。
- 技术栈:TypeScript strict、React 19、Tailwind CSS 4;零新增依赖。
- `.reference/` 只读;移植文件头标注来源与 MIT。

## 7. 验收标准

### 7.1 验收条目

1. 设置里选任一套界面主题,界面配色立即变化,重启后保持。
2. 设置里选任一套终端主题,已开终端立即换配色,重启后保持。
3. 首次启动(无设置)时落到默认主题 GitHub Dark。
4. 改终端主题/字体/字号/字重/行高/光标,预览块即时反映,已开终端即时生效。
5. 字体改动后终端无右侧空白带,观感与现有基线一致。
6. 字号/字重改动后终端网格与 PTY 同步,TUI 应用画面不乱。
7. 系统深浅变化不影响应用观感(已不跟随系统)。
8. shell 改动对之后新开的终端生效;回滚行数按重建语义生效。
9. 旧数据文件(有三态与双槽字段)打开不报错,自动迁到新字段并落默认主题。
10. 标题栏不再有主题三态按钮;设置入口(齿轮)可用。

### 7.2 测试接缝

- 接缝一:主题选择解析——三态 + 系统深浅 + 双槽,解析出当前应套用的主题;纯函数。
- 接缝二:终端外观解析——设置解析出终端配置与配色;纯函数;现有终端字体回归测试扩展为「来自设置」版本。
- 接缝三:设置读写向后兼容——缺字段补默认值;现有持久化 fixture 回放扩展。
- 其余(html 类应用、组件接线)复用现有接缝。新接缝仅上述三处纯函数,理由:主题与终端外观的规则密度高,值得纯函数直测;UI 接线沿用现有组件测试模式。
