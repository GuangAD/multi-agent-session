## 0. 准备

1. 启动:`pnpm dev`(首次启动前先确认 `store.json` 位置,见下)
2. 数据路径(开发态):`%APPDATA%\soloport\store.json`
   - 不确定时:改任意一项设置,再看 `%APPDATA%` 下哪个目录的 `store.json` 修改时间刚刚变了
3. **先备份**:把 `store.json` 复制一份到 `%APPDATA%\soloport\store.json.bak`(后续迁移测试要用,也防测坏)
4. 测试期间保持一个终端(`cmd`)开着,便于看落盘内容:`type %APPDATA%\soloport\store.json`
5. 记录方式:每条记「编号 + 通过/失败 + 失败现象(截图)」;`pnpm dev` 的终端窗口不要关,报错会打在那里

## A. 静态可见性(不用点任何控件,10 秒能判)

### A1 标题栏清理(验收 10)
- 操作:看窗口标题栏右侧
- 预期:有「齿轮」按钮;**没有**月亮/太阳/显示器三态主题按钮
- 失败典型:还能看到月亮/太阳图标;或齿轮不见
- 补充:项目行「…」菜单里**不应再有**「设置」项(2026-11-24 用户要求只留标题栏齿轮一处);若还能看到,记为回归

### A2 设置对话框开合(验收 10)
- 操作:点齿轮 → 按 `Esc`;再点齿轮 → 点「✕」;再点齿轮 → 点「完成」;再点齿轮 → 点面板外的遮罩
- 预期:四种方式都能关;零项目时齿轮也能打开(不必先建项目)
- 失败典型:某种方式关不掉;或需要先建项目才能打开

### A3 分区顺序与文案
- 操作:打开设置,从上往下看
- 预期顺序:界面主题(一个下拉)→ 预览块 → 终端主题(一个下拉)→ 终端外观(字体/字号/字重/行高/光标样式/光标闪烁)→ 通用(默认 Shell / 回滚缓冲区行数)
- 预期:没有「主题模式」三段控件(跟随系统/浅色/深色);预览块右上角**没有**月亮/太阳切换钮

## B. 界面主题(12 套单槽)

### B1 深色组 5 套逐个切换(验收 1)
- 操作:界面主题下拉 → 「深色」组里逐套选:GitHub Dark → GitHub Dark 高对比 → VS Code Dark Modern → Carbonfox → Tango Dark
- 预期(每套都要满足):
  - 侧栏、内容区、对话框、按钮、边框、文字**同时**换色,没有某一块保持原色
  - 右上角系统按钮区(最小化/最大化/关闭)的背景跟着换,不停在近黑
  - 内容区底色与侧栏底色**能看出分层**(不是同一种颜色)
- 失败典型(都是此前踩过的):侧栏/右栏不变色(只随明暗二值变);右上角不变色;侧栏与内容区一片死板同色
- 参考色(判"换没换"用):GitHub Dark 近黑 `#0d1117`,VS Code Dark Modern 偏灰 `#1f1f1f`,Carbonfox 带蓝调 `#161616`,Tango Dark 深灰

### B2 浅色组 7 套逐个切换(验收 1)
- 操作:同上,浅色组:VS Code Light+ → GitHub Light → Gruvbox Light 高对比 → Selenized White → Tango Light → Flexoki Light → Tomorrow
- 预期:每套都整体换色,文字仍清晰可读(无白底白字/黑底黑字)
- 重点看三处用户指定主色:
  - **GitHub Light**:主按钮是**纯黑**(`#000000`)底
  - **GitHub Dark / GitHub Dark 高对比**:主按钮是**蓝** (`#0078d4`)
  - **Gruvbox Light 高对比**:背景米黄(`#f9f5d7`)、主按钮黑
- 失败典型:按钮仍是灰/蓝但应黑;或某套浅色主题下侧栏是纯白、和内容区完全不分层

### B3 重启保持(验收 1)
- 操作:选一套明显不同的(如 Gruvbox Light 高对比)→ 完全关掉 `pnpm dev` → 重新 `pnpm dev`
- 预期:启动后就是那套,**首帧不闪错色**(不应先黑一下再变白)
- 失败典型:回到默认深色;或首帧闪一帧深色再跳变(首帧按默认 github-dark 落类,浅色主题会有一瞬深色;一帧内可忽略,超过 ~0.3 秒算失败)

### B4 首次启动默认(验收 3)
- 操作:把 `store.json` 改名成 `store.json.testbak` → `pnpm dev` → 看界面
- 预期:深色,且是 **GitHub Dark**(近黑 `#0d1117`,主按钮蓝)
- 失败典型:浅色;或深色但明显不是 GitHub Dark
- 测完把文件改回原名(或保留备份那份)

### B5 下拉弹层可读性(此前踩过)
- 操作:展开界面主题下拉、终端主题下拉
- 预期:展开的选项列表是**深底浅字**(深色主题下)或浅底深字(浅色主题下),不是白底浅灰字;长名字不被截断
- 失败典型:白底浅灰字几乎看不清;或名字被截成「Ghostty Defa」

## C. 终端主题与外观

### C1 终端主题 22 套分组(验收 2)
- 操作:开一个终端(新建会话,等 agent 起来)→ 终端主题下拉:深色组 13 套、浅色组 9 套
- 预期:逐套切换,**已开终端立即换配色**(不用重开),下拉里没有重复项
- 失败典型:改了没反应;或要关掉再开才变

### C2 明显差异对照(验收 2)
- 操作:在已开终端里跑一条带颜色的命令(如 `dir` 或 pi 的界面),切 `Ghostty Default Style Dark` ↔ `Tango Dark`
- 预期:背景色、绿色/红色/黄色系明显不同
- 失败典型:只有背景变、ANSI 色不变;或完全不变

### C3 字体与字号即时生效、无空白带(验收 4、5)
- 操作:外观区 → 字体选 `Consolas`(或 `Cascadia Mono`)→ 再改字号 14 → 20
- 预期:已开终端立即换字体/变大,**网格与画面匹配**,右侧没有一条空白带(横向没被用满)
- 失败典型:字号变了但字符宽度与网格不匹配(右侧空白带);或画面被压扁/重叠

### C4 行高、光标(验收 4、6)
- 操作:行高 1.0 → 1.5;光标样式 方块 → 竖线 → 下划线;光标闪烁 开
- 预期:行距肉眼变大;光标形态与闪烁立即变化;TUI(如 pi 或 `vim`)画面不错行、不花屏
- 失败典型:TUI 里文字重叠;或光标不闪

### C5 预览块如实反映(验收 4)
- 操作:盯着预览块,依次改:终端主题、字体、字号(20)、字重、行高、光标
- 预期:预览每次同步变化,且观感与**同一个已开终端**一致(两边同字体同配色);字号变大时预览内可出现滚动条,但**不截断**
- 预期2:预览块上**没有**深浅切换钮
- 失败典型:预览不动;或预览与实际终端字体/配色明显不一致(两副面孔)

### C6 回滚行数与隐藏标签(验收 8、终审 P1-2)
- 操作:开两个终端标签 A、B;切到 A(让 B 隐藏);在同一界面把「回滚缓冲区行数」改成 `25000` 并回车
- 预期:A 立即重建(画面清空重绘);切回 B 时 B 也正常重绘、`pi` 之类 TUI 不错位、不花屏
- 失败典型:切回 B 时画面挤成极窄两列(2×1 网格)、TUI 错位(说明隐藏态被 fit 过)

### C7 数字输入草稿态(J-003)
- 操作:字号输入框全选 → 键入 `16`;再把回滚行数全选 → 键入 `25000`,**不回车**先看终端有没有动静,再回车
- 预期:字号能输成 16(不被逐键夹成 8);回滚行数在失焦或回车**之后**才生效一次,输入期间终端不重建
- 失败典型:字号打不进 16(刚输「1」就变 8);或每敲一个键终端就闪一下重建

## D. 主进程原生控件(验收 7)

### D1 系统深浅不影响观感
- 操作:选一套**浅色**界面主题(如 VS Code Light+)→ 去 Windows 设置把系统切「深色」→ 回应用看
- 预期:应用仍是浅色,右上角系统按钮区仍是浅色主题的底色;切回系统浅色也无变化
- 失败典型:应用跟随系统变深/变浅

### D2 冷启动 overlay 着色(本轮 Critical 修复的验证点,重点测)
- 操作:选 `VS Code Light+`(浅色)→ 完全退出 → `pnpm dev` 重启 → **立刻**看右上角系统按钮区
- 预期:从第一帧起就是浅色底 + 深色图标,**不是**黑块
- 失败典型:右上角是近黑 `#0d1117`(说明走了默认主题),改一下任意设置后又变浅(说明只有设置变更路径生效)

## E. 旧数据迁移(验收 9)

### E1 第一版 store.json 启动不报错
- 操作:先退出应用 → 把 `store.json` 的 `settings` 段替换成下面这段(其余字段保留)→ 启动
```json
"settings": {
  "scrollbackRows": 10000,
  "theme": "light",
  "shell": "cmd",
  "appThemeDark": "warm",
  "appThemeLight": "rose",
  "terminalThemeDark": "Nope Dark",
  "terminalThemeLight": "Builtin Tango Light",
  "terminalFontSize": 16,
  "terminalFontWeight": 400,
  "terminalLineHeight": 1.2,
  "terminalCursorStyle": "bar",
  "terminalCursorBlink": true
}
```
- 预期:
  - 启动不报错、不弹异常、不生成 `store.json.corrupt-*`
  - 界面是 **GitHub Dark**(旧 `warm` 不在新目录 → 落默认)
  - 终端主题是 **Builtin Tango Light**(深槽名字坏了,**应退到浅槽**,不是落默认深色)
  - 字号 16、字重 400、行高 1.2、光标竖线 + 闪烁**全部保留**
- 失败典型:报错/白屏;或终端落成 `Ghostty Default Style Dark`(说明没有"依次试")

### E2 旧键不再写回
- 操作:承上,改任意一项(如把字号改 14)→ `type %APPDATA%\soloport\store.json`
- 预期:`settings` 里**只剩** `appTheme` / `terminalTheme` 两个主题字段;`theme`、四个旧槽键名全部消失
- 失败典型:旧键还在(说明写回时没删)

### E3 完全缺设置的新文件
- 操作:退出应用 → 把 `store.json` 的 `settings` 改成 `{}` → 启动
- 预期:不报错,全部设置落默认(深色 GitHub Dark、Ghostty 深色、字号 14、行高 1.0、回滚 10000)
- 测完用备份还原

## F. 通用区与回归

### F1 shell 只影响新终端(验收 8)
- 操作:默认 Shell 从 `powershell` 改成 `cmd` → 已开的会话不动;新开一个会话,在 agent 里退出(Ctrl+C 或 `/exit`)回到常驻 shell
- 预期:新会话回落的 shell 是 `cmd`(提示符类似 `C:\...>`);老会话仍是原来的
- 失败典型:老会话也变了;或新会话仍是旧 shell

### F2 落盘完整性
- 操作:把外观六项、两个主题、通用两项都改一遍 → 完全重启
- 预期:重启后**全部**是你最后选的值
- 失败典型:某项回退(说明 patch 没落盘)

### F3 视觉一致性复核(ADR-0008 仍有效)
- 操作:在 3 套差异大的主题下(深:GitHub Dark;浅:VS Code Light+、Gruvbox Light 高对比)扫一遍:侧栏、文件面板、Git 面板、设置对话框、下拉弹层、滚动条
- 预期:没有某一块"半深半浅"(如深色主题下某个面板是白底、按钮字看不见);滚动条与主题协调
- 失败典型:任何局部保持默认灰

### F4 无回归:会话/PTY 基础可用
- 操作:用迁移后的设置开一个会话,跑 `pi` 或 `vim` 各 1 分钟,打字、翻历史、拖窗口改大小
- 预期:输入正常、画面不错位、改窗口大小后网格与 PTY 一致(无空白带、无重叠)
- 失败典型:输入丢字、TUI 错位、窗口缩放后网格不同步
