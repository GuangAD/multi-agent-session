# T2 设置结构扩展与兼容

> 依赖:无 | 对应:brief 第 2 节目标 8、spec 覆盖标准接缝三

## 实现方式

**干什么**:Settings 增加界面主题双槽、终端主题双槽与终端外观六项,落盘读入自动补默认,IPC 写入校验夹紧。

**输入**:渲染层的 `settings:set` patch;store.json 既有内容。

**处理**

1. `src/shared/types.ts` 按 spec 数据结构节扩展 Settings。
2. `DEFAULT_STORE.settings` 补全部新字段默认值(loadStore 的「缺字段补默认」展开逻辑自动兼容旧文件)。
3. `applyPatch` 扩展新字段校验并导出供单测。
4. 主题 id 字段只验「非空字符串」,内容合法性交给解析兜底(spec 约定,不做白名单)。

**失败与退出**:坏值一律忽略或夹紧,不抛出;落盘仍走既有原子写,失败时控制台报错。

## 接口(伪代码)

落点:`src/shared/types.ts`、`src/main/session-store/store-persistence.ts`、`src/main/ipc/settings.ts`

```ts
interface Settings {
  // ……既有字段不动;新字段形状定义见 spec.md 数据结构节,不得在此改变
}

// DEFAULT_STORE.settings:在既有三字段之外按 spec.md 数据结构节注释的默认值逐字段补齐

applyPatch(settings: Settings, patch: Partial<Settings>): void
  // 用途:把渲染层 patch 合入内存设置,坏值挡在 store 之外
  // 怎么用:原地修改 settings;每次调用独立,无顺序要求
  // 出错时:不抛出;非目标类型的字段直接忽略,数值越界按边界夹紧
```

校验细则:

- 四个主题槽:非空 string 才写入;`terminalFontFamily`:string(含空串)才写入,空串 = 默认回退链。
- `terminalFontSize`:有限数字才处理,trunc 后夹紧 [8, 32]。
- `terminalFontWeight`:仅 300/400/500 写入,其余忽略(三档是用户可感知档位,不做就近夹紧)。
- `terminalLineHeight`:有限数字才处理,夹紧 [1.0, 2.0],保留一位小数。
- `terminalCursorStyle`:仅 'block' | 'bar' | 'underline';`terminalCursorBlink`:仅 boolean。

## 开发步骤
1. types.ts 扩展 Settings(定义见 spec 数据结构节)。
2. 写 loadStore 兼容测试(期望值来源:spec 接缝三矩阵):旧文件全缺 → 补默认;全字段 → 保留;部分缺 → 缺补有不洗;settings 非对象 → 既有损坏兜底不回归。
3. 运行 `pnpm vitest run src/main/session-store/store-persistence.test.ts`;Expected: FAIL(exit 1),`4 failed`,红因是 DEFAULT_STORE.settings 尚无新字段默认值。
4. store-persistence.ts 的 DEFAULT_STORE.settings 按 spec 数据结构节注释补齐默认值。
5. 复跑步骤 3 命令;Expected: PASS(exit 0),`4 passed`,且不是 0 passed。
6. 写 applyPatch 用例(新建 `src/main/ipc/settings.test.ts`,期望值来源:brief 第 5 节默认值边界):越界 fontSize 3/99 → 8/32;lineHeight 0.5/3 → 1.0/2.0;fontWeight 350 → 忽略;cursorStyle 'wavy' → 忽略;主题槽 123(数字)→ 忽略;合法 patch → 全字段写入。
7. 运行 `pnpm vitest run src/main/ipc/settings.test.ts`;Expected: FAIL(exit 1),`6 failed`,红因是 applyPatch 未导出且新字段无校验。
8. settings.ts 的 applyPatch 导出并扩展校验(校验细则见上)。
9. 复跑步骤 7 命令;Expected: PASS(exit 0),`6 passed`,且不是 0 passed。
10. 运行 `pnpm typecheck`;Expected: exit 0。
11. 运行 `pnpm test`;Expected: exit 0,全绿(此时下游任务的用例尚未存在,不要求新增条数)。
