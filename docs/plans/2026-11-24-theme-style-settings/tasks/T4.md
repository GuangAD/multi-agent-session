# T4 界面主题数据与选择应用

> 依赖:T1、T2 | 对应:brief 第 2 节目标 2、4;spec 覆盖标准接缝一(界面侧)、接缝四(界面目录)

## 实现方式

**干什么**:落 8 套界面主题数据与主题选择解析,把界面套色接到「html 唯一写手」,渲染层设置状态就位。

**输入**:设置(形状来自 T2)、系统深浅、token 层(T1 的 theme-tokens.css)。

**处理**

1. `app-themes.ts` 按下方色值表落 8 套数据(default = zinc 基准,其余七套按呼应色系)。
2. `theme-tokens.css` 增加 `.theme-<id>`(与 `.dark.theme-<id>`)变量覆盖;'default' 不挂类,即 :root 默认。
3. `resolve.ts` 增加 selectAppTheme(与 selectTerminalTheme 同口径)。
4. `theme.ts` 的写手升级为 applyAppearance(dark, appThemeId):写 dark 类 + 主题类;三态循环按钮与启动初载改走它,行为不变。
5. 新建 `settings-slice.ts`(渲染层设置状态):初载 loadSettings、updateSettings 发 patch 存返回值;ThemeToggle 改用 slice 持有三态。

**失败与退出**:解析坏 id 落 default;IPC 失败沿用「显示不回滚、控制台报错」既有策略。

## 开发步骤

1. 建 `app-themes.ts` 按上表落 8 套(浅/深共 16 形态)。
2. 建 `app-themes.test.ts` 写目录完整性用例(期望值来源:上表 + 色值格式约定):恰 8 套、id 唯一且属联合类型、两形态 9 token 齐、色值 #rrggbb。
3. 运行 `pnpm vitest run src/shared/themes/app-themes.test.ts`;Expected: FAIL(exit 1),`1 failed`,红因是 app-themes.ts 尚不存在;完成步骤 1 后复跑;Expected: PASS(exit 0),`1 passed`,且不是 0 passed。
4. `resolve.test.ts` 追加界面侧用例 1-6(编号对齐 spec 接缝一)。
5. 运行 `pnpm vitest run src/shared/themes/resolve.test.ts`;Expected: FAIL(exit 1),`6 failed`,红因是 selectAppTheme 未实现。
6. 实现 selectAppTheme;复跑;Expected: PASS(exit 0),`16 passed`(原 10 条 + 新 6 条),且不是 0 passed。
7. `theme-tokens.css` 追加 7 套主题的 `.theme-<id>` 与 `.dark.theme-<id>` 变量覆盖(default 不挂类)。
8. `theme.ts` 实现 applyAppearance 并删除 applyDarkClass,ThemeToggle 改调用。
9. 建 `settings-slice.ts`;ThemeToggle 的持久化与初载改走 slice(三态循环、系统跟随行为不变)。
10. 运行 `pnpm typecheck`;Expected: exit 0。
11. 运行 `pnpm test`;Expected: exit 0,全绿。
12. 冒烟 `pnpm dev`:三态循环不变;手改 store.json 的 appThemeDark 为 'warm' 重启,界面呈暖米深色;改回 'default' 无痕。
