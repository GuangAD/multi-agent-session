# Git worktree 会话 · 门 3 冒烟清单

> 2026-11-26 | 对照 brief 7.1 的 14 条 + 终审提出的两条跨特性风险。
> 每条给「操作 → 预期 → 判定依据」。**没跑过的项不许标通过**。

## 0 前置准备

| 步骤 | 操作 | 预期 |
|---|---|---|
| 0.1 | `pnpm install`(如未装),`pnpm dev` | 应用起窗口,无报错 |
| 0.2 | 准备测试仓库:`git init /tmp/wt-demo && cd /tmp/wt-demo && git commit --allow-empty -m init && git branch dev` | 仓库有 2 个分支(`master`/`main` 与 `dev`) |
| 0.3 | 应用里「+」添加 `/tmp/wt-demo` 为项目;再加一个**非 git 目录**(如 `/tmp/plain-demo`) | 侧栏出现两个项目 |
| 0.4 | 确认至少一个 agent 已安装(弹窗里不带「未安装」小字) | 至少 1 个可点条目 |

记录环境:git 版本、agent 名称、是否首次运行。

## A 入口可见性(brief 7.1-1)

| # | 测试项 | 操作 | 预期 |
|---|---|---|---|
| A1 | 非 git 项目不显示入口 | `plain-demo` 行「…」 | 菜单只有「导入历史会话」「移除项目」两项,无「建 worktree 会话」 |

## B 创建(brief 7.1-2/3/12)

| # | 测试项 | 操作 | 预期 |
|---|---|---|---|
| B1 | 正常创建 | 「…」→「建 worktree 会话」→ 起点分支选 `dev` → 名称填 `feat-a` → 点已安装 agent | 弹窗关闭;侧栏该项目下新增会话,标题下有小字 `feat-a`;标签页已打开 |
| B2 | 磁盘产物 | 终端里 `cd /tmp/wt-demo && git worktree list` | 出现 `/tmp/wt-demo/.worktree/feat-a` 条目 |
| B3 | 分支基于起点 | `git log --oneline --decorate -1 feat-a` 与 `git log -1 dev` | 两者 HEAD 一致;`git branch --contains feat-a` 里能看到 `feat-a` |
| B4 | 排除文件写入 | `cat /tmp/wt-demo/.git/info/exclude` | 末尾有 `.worktree/` 一行;`.gitignore` **未**被改动 |
| B5 | 排除幂等 | 再建 `feat-b` 后重看 exclude | `.worktree/` 仍只有一行 |
| B6 | 目录名冲突 | 名称填 `feat-a`(已存在)再提交 | 弹窗内出现「目标目录已存在」类错误;磁盘无变化,不落记录 |
| B7 | 名称非法 | 名称填 `feat a`(带空格)再提交 | 弹窗内出现名称错误提示;一条 git 命令都不执行 |
| B8 | 分支名冲突 | 名称填一个已存在的分支名(如 `dev`)再提交 | 弹窗内显示 git 原文(already exists);不落记录 |
| B9 | 会话占用 | 手工把会话 A 的 worktree 记到同名路径(或不删会话 B 再建同名字) | 手段见备注;预期「已有会话占用该路径」 |
| B10 | 未安装置灰 + Esc | 打开弹窗看未安装条目;按 Esc | 未安装条目点不动且带「未安装」小字;Esc 关闭,无副作用 |
| B11 | 空仓库 | 新建 `git init` 但**无任何提交**的仓库并添加为项目,打开弹窗 | 显示「该仓库还没有任何分支(先提交一次…)」,不可提交 |

> B9 备注:直接构造冲突最省事的办法是在 `git worktree list` 已含该路径的情况下重试(先建 `feat-c`,不删会话,再建 `feat-c`)。

## C 终端运行目录与续接(brief 7.1-4/5)

| # | 测试项 | 操作 | 预期 |
|---|---|---|---|
| C1 | 终端在 worktree 里跑 | 在 B1 的会话里让 agent「创建一个 hello.txt 文件」,然后看磁盘 | 文件出现在 `/tmp/wt-demo/.worktree/feat-a/hello.txt`,**不在** `/tmp/wt-demo/` |
| C2 | 备选判据(不做 C1 时) | 打开该会话几秒后 `ls -a /tmp/wt-demo/.worktree/feat-a` | 出现 `.claude/`、`.codex/`、`.agents/`、`.pi/` 之一(见 H1,同时是风险判据) |
| C3 | 重开在同一目录 | 关掉该会话标签页 → 侧栏点会话重开 | 终端仍在 worktree 目录:重复 C1 或 C2 的判据 |
| C4 | 续接是否真的续接 | 重开后在 agent 里问「上一条消息是什么」 | 若拿到了 `externalSessionId` 应能续接;**拿不到 = H2 命中**(原样拉起) |

## D 面板跟随(brief 7.1-6/7/8)

| # | 测试项 | 操作 | 预期 |
|---|---|---|---|
| D1 | worktree 会话 → 面板跟 worktree | 切到 `feat-a` 会话,右栏切「文件」面板 | 树根是 `.worktree/feat-a` 的内容(能看到 C1 的 `hello.txt`) |
| D2 | 同上,Git 面板 | 右栏切「Git」面板 | 显示的是 worktree 目录的 git 状态(分支 `feat-a`),不是项目根 |
| D3 | VS Code 打开跟随 | 点标题栏 VS Code 图标 | 打开的是 `.worktree/feat-a`;aria-label 为「通过 VS Code 打开当前目录」 |
| D4 | 普通会话 → 面板跟项目 | 切到一个普通会话(项目根跑的) | 面板根是 `/tmp/wt-demo`,不是 worktree |
| D5 | 无标签回落选中项目 | 关掉全部标签页,侧栏选中 `wt-demo` | 面板显示 `/tmp/wt-demo` 内容,不空白 |
| D6 | 两者皆无 | 关掉全部标签页,再取消/删除选中项目 | 面板显示空态文案,不报错 |

## E 删除(brief 7.1-9/10/11 + P2 风险)

| # | 测试项 | 操作 | 预期 |
|---|---|---|---|
| E1 | 干净会话直接删 | **先做 H1 的判定**,再做本项:在 worktree 里没有任何改动的会话上点删除 → 确认 | 目录消失,`git worktree list` 不再含它;会话从侧栏移除、标签页关闭 |
| E2 | 有未提交改动先拒 | 在 worktree 里留一个未提交改动(B1 的 hello.txt 不提交即可),点删除 → 确认 | 确认框原地变成「强制删除会话…」,正文含 git 原文(`contains modified or untracked files`);**目录与记录都还在** |
| E3 | 二次确认强删 | E2 之后点「强制删除(丢弃未提交改动)」 | 目录消失、记录消失;分支 `feat-a` **仍存在**(`git branch` 可见) |
| E4 | 目录已手工删 | 另一条 worktree 会话:直接 `rm -rf /tmp/wt-demo/.worktree/<名>`(登记还在),再点删除 | 幂等成功:记录消失,无报错 |
| E5 | 取消不留残局 | E2 的第二步点「取消」 | 目录与记录都保留;确认框关闭 |
| E6 | 取消后框不该自己弹回来(T5 Important) | 点删除后**立刻**点「取消」,然后等 2~3 秒 | 框保持关闭,不再自动弹出 |
| E7 | 强删无出口循环(P2) | 对 E4 之后仍删不掉的场景(若遇到),连点两次「强制删除」 | 若两次都是同一句原文,应切到「知道了」式只报原文的框(而非无限重复) |

## H 判定项(终审提出的两条跨特性风险)

这两条不是「验一下功能」,而是「判定要不要改代码」。**先跑 H1,结果决定 Important-1 的修法**。

| # | 测试项 | 操作 | 预期 / 判定 |
|---|---|---|---|
| H1 | hook 注入是否弄脏 worktree | 建一个 worktree 会话并让它真的启动 agent,然后在 `/tmp/wt-demo/.worktree/<名>` 里跑 `git status --porcelain` | **空** = 无此问题;**非空(出现 `.claude/`、`.codex/`、`.agents/`、`.pi/`) = Important-1 成立**,E1 会稳定失败、每次删除都要强删。此时请回我 A/B/C 选哪个 |
| H2 | worktree 会话能否续接 | 开 worktree 会话 → 让 agent 说一句话 → 关标签 → 重开 → 问它「上一条消息是什么」 | 答得出来 = 续接正常;**答不出/全新会话 = Important-2 成立**(回填按项目路径扫描,永远找不到 worktree 的 transcript),同时观察同项目 5 分钟内新开普通会话是否也拿不到续接 |
| H3 | Git 面板是否长期挂未跟踪目录 | 打开 worktree 会话的 Git 面板 | 若长期显示 `.claude/`、`.codex/` 等未跟踪目录 = H1 的可见症状 |
