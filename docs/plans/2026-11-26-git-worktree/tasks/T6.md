# T6 收尾:冒烟暴露的两条跨特性问题 + 终审 4 条 P2

> 依赖:T5 | 对应:终审 Important-1(用户裁定 A)/ Important-2 / P2-1~P2-4;冒烟 H1、H2、H3

## 实现方式

**干什么**:worktree 会话第一次让 agent 在项目目录之外运行,撞出两个旧接缝的问题——hook 注入把 worktree 弄脏、回填按项目路径扫描找不到 transcript;连同终审的 4 条 P2 一并收掉。

**输入**:创建 worktree 的项目路径;spawn 后的会话记录(可能带 worktree);删除确认框的点击。

**处理**

1. 写排除文件时不再只写 `.worktree/`,同时写 hook 注入会在工作区留下的四个顶层目录(`.claude/`、`.codex/`、`.agents/`、`.pi/`),一行一个、幂等。`git/info/exclude` 是仓库级,链式 worktree 与被链仓库共享,故 worktree 内的 `git status` 同样干净。
2. 回填的扫描路径改用会话运行目录(`resolveSessionDir`),标题补捞同源。
3. 回填资格的「同一格」判据加上 worktree 路径:同 agent + 同项目 + 同 worktree 才算冲突(两个不同 worktree 是两个 transcript 桶,互不干扰)。
4. 强制删除再失败时切到「只报原文」态,不再原地循环。
5. `.worktree/` 前缀判定前先 `resolve()`,堵住记录里带 `..` 时删到该目录之外。
6. 弹窗提交期给出「正在创建…」并允许关闭(创建仍会在后台完成并开标签页)。

**失败与退出**:1 与 2 的失败面不变(写排除失败仍只告警;扫描失败仍放弃回填)。4 让用户拿到明确终点而不是无限重试。
