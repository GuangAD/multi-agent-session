# T3 删链路:删会话连带删 worktree

> 依赖:T2 | 对应:brief 第 2 节目标 8、spec 覆盖标准 4/5/10/12

## 实现方式

**干什么**:删带 worktree 的会话时先把磁盘目录清干净,再删记录。

**输入**:会话 id、可选的强制参数;主进程自取会话记录与项目路径。

**处理**

1. 会话没有 worktree → 走今天的老路,一条 git 命令都不执行。
2. 有 worktree → 先探两件事实:目录在不在(`fs`)、git 还认不认它(`worktree list`)。
3. 按两件事实选动作:`remove` / `prune` / `skip`。
4. 动作失败(通常是未提交改动)→ 原样回传 git 原文,记录不动。
5. 动作成功或无需动作 → 删记录,连带关活动标签页。

**失败与退出**:清不掉目录就整件事不成立,回 `worktreeError`;调用方带 `forceWorktree` 再来一次。

## 接口(伪代码)

落点:`src/main/git-worktree.ts`

```ts
pickRemovalAction(p: { dirExists: boolean; registered: boolean }): 'remove' | 'prune' | 'skip'
  // 用途:决定用哪种 git 动作清掉一个 worktree
  // 怎么用:纯函数;两者都在 → remove,只在 git 登记 → prune,都不在 → skip
  // 不会失败

removeWorktree(p: {
  root: string
  path: string
  force: boolean
  service: WorktreeService
  dirExists: (path: string) => Promise<boolean>
}): Promise<{ ok: true } | { ok: false; error: string }>
  // 用途:把「探事实 → 选动作 → 执行」串成一次可测的清理
  // 怎么用:无状态,每次调用重新探事实;service 与 dirExists 可注入,单测不必打真实 git
  // 出错时:返回 ok:false 与 git 原文,不抛;清理未成功时目录与记录都不该被改动

// WorktreeService 增加两个动作
remove(p: { root: string; path: string; force: boolean }): Promise<void>
  // 用途:删一个 worktree
  // 怎么用:force 为 true 时带 --force 丢弃未提交改动;调用前先过 pickRemovalAction
  // 出错时:抛 git 原文

prune(root: string): Promise<void>
  // 用途:清掉 git 里指向已消失目录的残留登记
  // 怎么用:幂等,可重复调用
  // 出错时:抛 git 原文
```

落点:`src/main/ipc/sessions.ts`

```ts
remove(id: SessionId, options?: { forceWorktree?: boolean }): Promise<{
  closedTabs: SessionId[]
  worktreeError?: string
}>
  // 用途:删会话的入口;带 worktree 时先删目录再删记录
  // 怎么用:worktreeError 存在即表示一件事都没删,可带 forceWorktree 再调一次
  // 出错时:不抛,错误放在 worktreeError 里给渲染层显示
```

9. 补实现
10. 运行:同上;Expected: PASS(exit 0),`Tests 3 passed (3)`
11. 接线:`shared/ipc-contract.ts` 的 `SessionsApi.remove` 加可选参数与可选 `worktreeError`;`main/ipc/sessions.ts` 的 handler 先调 `removeWorktree`,失败即返回、不删记录。无自动化用例。

15. 收尾:`pnpm vitest run src/main/git-worktree.test.ts`;Expected: PASS(exit 0),`Tests 21 passed (21)`(T2 在本文件的 16 条 + 本任务 5 条)
