# Git worktree 会话 · 设计说明

> 2026-11-26 | 状态:已批准 | 档位:完整

## 1. 背景与问题

一个项目现在只有一份工作副本。想让两个会话同时干活,只能手工切分支,或者等前一个干完。

应用本身支持多会话并行,但并行会话共用同一份工作副本,必然互相踩文件。git 的 worktree 能给出互不干扰的副本,而应用里没有任何入口。

结果:需要并行时,用户只能离开应用去命令行建 worktree,再手工把那个目录当成新项目添加回来。

## 2. 目标 · 非目标 · 失败形态

**目标**

- 项目行「更多」菜单提供「新建 worktree」,仅对「项目目录本身是 git 仓库根」的项目显示。
- 一个弹窗内选起点分支、填名称、选 agent,一次动作完成建目录与建会话。
- worktree 目录落在项目目录下的 `.worktree/<名称>`,名称同时作新分支名。
- 新分支从所选起点分支切出,不复用任何已有分支。
- `.worktree/` 自动写入该仓库的本机排除文件,不改 `.gitignore`。
- 新会话挂在该项目下,终端在 worktree 目录里运行 agent。
- 重开该会话,仍在 worktree 目录里续接。
- 删除该会话时连带删 worktree 目录;有未提交改动先拒绝,二次确认才强删。
- 右侧文件树、Git 面板与「在 VS Code 打开」显示当前活动会话所在目录。

**非目标**

- 不做 worktree 的独立管理界面:列出、切换、删除、重命名都不做。
- 不扫描 `.worktree/`,不把已有目录导入成会话或项目。
- 不支持远端分支,不支持批量创建。
- 不允许多条会话共用同一个 worktree。
- 不改 `.gitignore`,不改会话行除分支小字外的渲染,不动运行状态与通知。
- 移除项目时不删磁盘上的 worktree 目录。
- 删除会话时不删新分支。

**失败形态**

- agent 仍在项目主目录里运行,改动落到主副本的分支上。
- `.gitignore` 或本机排除文件被覆盖,用户仓库被污染。
- 分支名被占用时提示含糊,用户以为已经建好了。
- 面板跟着切标签后空白或报错,因为没处理无标签与已删除项目。
- 强删静默丢弃未提交改动。
- 建目录成功但会话没建成,留下有目录无会话的死角,同名重建又被规则挡住。

## 3. 选定方案

一条路:菜单项 → 弹窗(起点分支 + 名称 + agent) → 主进程建 worktree → 记本机排除 → 建会话并开标签页。

被否掉的方案:

- **注册成新项目**:会话挂在原项目下即可;同一仓库出现两个并列项目行,导入与去重都跟着变复杂。
- **两层弹窗(先建 worktree 再选 agent)**:中间态「有目录无会话」会把用户卡在冲突规则上,只能手工删目录重来。
- **面板不跟随**:worktree 会话干活时看不到 diff 也提交不了,新功能半残。
- **面板仅 worktree 会话跟随**:两套取数规则,读代码的人要先判断当前是哪一种。

## 4. 约束

- git 2.46 本机实测:同一分支不能被两个 worktree 检出。
- `git worktree remove` 在有未提交改动时拒绝执行,必须显式强删。
- 仓库根必须等于项目目录,否则不提供入口。
- 会话的运行目录只有一处来源,新建与重开两条路径都必须带上 worktree 目录。
- 会话记录新增可选字段:旧记录没有该字段仍可读,存储版本号不变,不做迁移。
- 主进程独占 git 与文件系统能力,渲染层只经桥接调用。
- 契约先行:通道名与载荷类型一一对应。
- 浮层用 fixed 定位,不挂在滚动容器内(J-008)。
- 设置类变更仍只走单一写手,面板跟随不属于设置(J-004)。

## 7. 验收标准

### 7.1 验收条目

1. 非仓库项目、或仓库根不是项目目录的项目:菜单里没有「新建 worktree」。
2. 正常创建:磁盘出现 `<项目>/.worktree/<名称>`,`git worktree list` 含它,新分支基于所选起点分支。
3. 本机排除文件含 `.worktree/`;同名重复创建不会重复写入。
4. 项目下出现新会话且标签页已开;会话内 `pwd` 证实在 worktree 目录。
5. 重开该会话:续接或原样拉起都发生在 worktree 目录。
6. 切到 worktree 会话:文件树与 Git 面板都在 worktree 目录。
7. 切到普通会话:面板跟该会话所属项目目录。
8. 关掉全部标签:面板回落到选中项目。
9. 删除该会话(无未提交改动):目录消失,`git worktree list` 不再含它。
10. 删除该会话(有未提交改动):先拒并显示 git 原文;二次确认后目录消失。
11. worktree 目录已被手工删除时删会话:幂等成功,不报错。
12. 同名目录已存在、或已有会话指向该路径:弹窗内报错,不创建任何东西。
13. 移除项目:项目与会话记录消失,磁盘上的 `.worktree` 目录保留。
14. `pnpm typecheck` 双投影 0 error,`pnpm test` 全绿,`pnpm build` 通过。

### 7.2 测试接缝

四条,全部纯逻辑;真实 git 行为由 7.1 的实机条目兜底。

- **会话记录带 worktree 字段**:沿用既有的记录持久化接缝,验读回与旧记录兼容。
- **面板目录计算**:新接缝,一个纯函数决定面板显示哪个目录。已有接缝不够用,因为目录选择原本散在两个面板组件内部。
- **worktree 命令构造与解析**:新接缝,纯函数覆盖参数拼装、`worktree list` 输出解析、名称合法性校验、排除文件幂等追加。
- **创建前的冲突判定**:新接缝,纯函数判定目录已存在与记录已占用两种冲突。

删除编排调用 git 的部分用一个可注入的执行器隔离,测试只看编排结果(是否强删、是否回滚记录),不打真实 git。

## 8. 授权项

- 通道命名、载荷字段名与参数形状。
- worktree 能力在既有 git 服务层内的落点与内部拆分。
- 弹窗与确认框的组件落点、骨架复用方式。
- 日志与内部错误消息文本(用户可见文案除外,见第 6 节)。
- 并发保护与失败重试的具体写法。
