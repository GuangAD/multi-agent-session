# 0010 - 会话携带 worktree 指针,worktree 不注册成项目

日期:2026-11-26 | 状态:已采纳

## 背景

应用的数据模型是「项目 = 用户添加的目录,会话的运行目录 = 该项目目录」(`shared/types.ts` 的 `Project`、`CONTEXT.md`「项目/会话」)。一个项目因此只有一份工作副本,并行会话共用它。

git 的 worktree 能给出互不干扰的副本。要让它可用,必须回答一个问题:worktree 目录算不算一个「项目」。

## 决策

- 会话记录增加可选的 worktree 指针,记目录、分支、起点分支三项;旧记录无此字段仍可读,存储版本号不变、不做迁移。
- worktree 目录固定为 `<项目>/.worktree/<名称>`,依附于所属项目,不进入项目列表。
- 会话挂在所属项目下,运行目录取 worktree 路径;重开同样在该目录续接。
- 删除该会话时连带删除 worktree 目录;有未提交改动先拒绝,二次确认才强删。分支保留。

## 为什么不用「把 worktree 目录注册成新项目」

- 项目行的语义是「用户添加的目录」。同一仓库拆成两个并列项目后,会话导入去重、hook 注入的项目级配置、移除项目连带删会话,三条既有逻辑都要按「这是一个 worktree 项目还是一个普通项目」分叉。
- 移除 worktree 时要再走一次「移除项目」,并额外判断这是不是应用自建的目录,多一层易错的判据。
- 会话与目录的归属会被拉直成「会话属于项目」,而 worktree 会话真正需要的是「会话属于项目,但在另一个副本里运行」。把副本升级成项目等于用更粗的结构表达更细的关系。

## 后果

- 好处:项目列表不被副本污染;并行会话与普通会话共用一套记录结构,只在有 worktree 时多三个字段。
- 好处:worktree 由应用创建,删除时连带删除不违背 ADR-0003「应用永不改写 agent 存储」——worktree 是应用自己的产物,不是 agent 的对话存储。
- 代价:会话记录多了一个可选字段,所有涉及会话序列化与比较的地方都要带上它。
- 代价:右栏面板的目录不再等同于选中项目,改由活动会话决定(见 `DECISIONS.md` J-009),面板与项目的耦合被拆开。
