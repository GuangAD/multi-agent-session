# 0009 - 界面主题改单一色板,取消深浅双槽与跟随系统

日期:2026-11-24 | 状态:已采纳 | 取代 ADR-0008 的槽结构部分

## 背景

ADR-0008 定的是「主题自带深、浅两形态 + 深/浅双槽 + 三态(含跟随系统)」,对标 Orca 的复杂插件主题生态。
第一版实现完成后,用户实机看过 65 套候选,提出两点:(1) 想要的主题极少同时具备高质量的深浅两形态;
(2) 双槽 + 跟随系统让自己的选择被系统悄悄改掉,不如直接选一套。

## 决策

- 每套界面主题 = **一组 token 值**(不再有 light/dark 两形态),带 `isDark` 标记。
- 设置里界面主题、终端主题各**一个下拉、单槽**,不跟随系统。
- 删除主题三态(`system/light/dark`)、标题栏三态循环按钮、设置里的「主题模式」控件。
- `isDark` 只承担两件事:页面 `color-scheme`(原生滚动条/表单控件)与主进程原生控件着色(标题栏 overlay、`nativeTheme.themeSource`)。

## 为什么不用「双槽 + 跟随系统」(ADR-0008 的方案)

- 主题生态的现实:绝大多数高质量配色只做一侧(如 Nord 无官方浅色、Alabaster 无深色),强行配对等于一半是拼凑。
- 用户明确表达了「不想被系统改掉自己选的主题」;三态带来的复杂度(每个下拉 ×2、每个主题 ×2 形态、解析函数多一个维度)在这个产品里没有对应收益。
- 语义 token 层不受影响:换主题依然只覆盖 `--app-*` 变量,组件零改动。

## 后果

- 好处:设置项减半,主题数据一维,解析函数从「三态 × 系统深浅 × 双槽」降为「取一个 id」;用户选什么就是什么。
- 代价:没有自动深浅跟随,用户在白天/夜晚需自己切换(或以后再加「按时间切换」这类功能)。
- 迁移成本:旧 `store.json` 的三态与双槽字段需要一次性映射(旧主题 id 已不存在,统一落默认主题)。
- ADR-0008 的「界面颜色只经语义 token 层」部分**继续有效**,仅其「深浅双槽」结构被本 ADR 取代。
