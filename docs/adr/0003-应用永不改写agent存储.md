# 0003 - 应用永不改写 agent 存储

日期:2026-11-20 | 状态:已采纳(其中「登记忽略清单」的机制条已被 ADR-0005 取代;核心决策「永不改写 agent 存储」不变)

## 背景

各 agent CLI 自己拥有并管理会话存储(格式互异:claude 的项目目录 jsonl、codex 的 rollout 与索引、kimi 的 state.json 加索引等),应用的会话记录只是指向它们的档案卡片。删除、重命名等管理操作存在「是否连带处理 agent 数据」的问题。

## 决策

应用对 agent 存储只读,永不写入或删除:

- 删除会话只移除应用记录,并登记 (agentId, externalSessionId) 到忽略清单,导入扫描遇之即跳过
- 重命名只改应用侧显示名,agent 侧原名与对话 id 常驻可查
- 用户要删除某个 agent 对话,去该 agent CLI 内操作

## 为什么不用「连带删除/同步改名」

- 误删真实对话数据不可恢复,而删错应用记录损失仅是一张档案卡片——风险极不对称
- 五套存储格式各异的写逻辑成本高,且写索引有损坏风险
- agent 自动生成的标题会覆盖应用写入的名字,「同步改名」保不住
- 改写 agent 存储违背领域原则:对话内容的唯一权威是 agent 存储(见 CONTEXT.md「agent 对话」词条)

## 后果

- 应用侧名字与 agent 侧名字允许不同;认亲靠「原名 + 时间 + id」,应用内常驻展示
- 删除后 agent 对话仍在,且不再被导入扫回;历史永不因应用操作而丢失
- 终端画面回滚是唯一「应用侧有界」的数据(见 ADR-0002),超出部分靠 agent 存储查证
