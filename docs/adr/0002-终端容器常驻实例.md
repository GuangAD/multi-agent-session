# 0002 - 终端容器常驻实例,不搬 serialize 重放

日期:2026-11-20 | 状态:已采纳

## 背景

Orca 的终端容器在切换标签页时销毁 xterm 实例,切回时新建实例并用 `@xterm/addon-serialize` 把先前导出的画面文本重放还原;PTY 数据在实例缺席期间攒着,重放后补上。该机制服务于其 daemon/多窗口/断线重连架构——「会话活着但画面无处显示」是常态。

## 决策

本应用为单窗口单进程:每个会话保有一个常驻 xterm 实例,tab 切换仅切换可见性;PTY 数据始终直灌对应实例。不搬 serialize 重放,不引入 `@xterm/addon-serialize` 依赖。

## 为什么不用 serialize 重放

- 不存在「会话活着而画面无处显示」的状态——窗口在,实例就在
- 常驻实例的画面天然最新,省掉导出/存储/重放一整层逻辑
- 少一个依赖;切走期间的输出持续写入隐藏实例,后台状态识别(屏幕快照源)照常工作

## 后果

- 每个会话常驻占内存:以 scrollback 上限控制(默认 10000 行,设置可调,硬上限 50000)
- 应用退出即全部终端进程结束(无 daemon),退出时全量清理不留孤儿
- 将来会话数多到内存吃紧,再引入「销毁最久未看实例 + 此时才用 serialize」的 LRU 作为可选优化
