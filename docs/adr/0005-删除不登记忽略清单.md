# ADR-0005:删除会话不登记忽略清单,再次导入直接重新入库

> 2026-11-21 | 状态:已接受(用户拍板,重过门 1) | 取代:ADR-0003 中「登记忽略清单」的机制条

## 背景

ADR-0003 定下的边界是「应用永不改写 agent 存储」,其中提到删除会话时把 `(agentId, externalSessionId)` 记入应用侧忽略清单,使导入扫描跳过已删会话,避免「删了又被扫回来」。T4、T6 按此实现:删除写 `store.ignoreList`,`runImport` 按忽略清单过滤。

T6 冒烟时用户提出相反诉求:**删掉的导入会话,再次导入时应当直接导回来**。理由是实际使用里「删」常用来清理视图,不是永久拉黑;被自己删掉的会话在 agent 存储里依然存在,重新导入却拿不回来,反而像数据丢失。

## 决策

1. 删除会话只移除应用记录(含连带关标签页),**不写任何忽略清单**。
2. 导入只按 `(agentId, externalSessionId)` 与现有记录去重;**不再有忽略清单过滤**。
3. `AppStore` 去掉 `ignoreList` 字段与 `IgnoreEntry` 类型。旧 `store.json` 里残留的 `ignoreList` 在 `loadStore` 中不再读取,下次整文件写入时自然丢弃(无需迁移代码)。
4. 连带修订:brief 第 5 节与验收 7.1、spec 覆盖标准接缝 path-match/runImport 第 5 行、`CONTEXT.md` 的「忽略清单」词条、PLAN.md M4 段、T6 用例 5 语义。

## 后果

- 正面:删除与重新导入互为逆操作,用户不会因为删过而永久拿不回列表项;少一个需要维护与解释的数据段。
- 负面:**「删了又被扫回来」重新成为可能**——用户如果只想清空列表又不想让它出现,目前没有永久手段。若将来确实出现这种诉求,新方案应是「导入时列出已删项由用户勾选」(显式选择),而不是回到自动拦截。
- 不变:应用依然只删自己的记录,永不改写 agent 存储(ADR-0003 的核心决策不受影响,被取代的只是它描述的那条机制)。
