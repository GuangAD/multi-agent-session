# 0007 - 状态识别走 hook 通道,读屏三源退役

日期:2026-11-24 | 状态:已采纳 | 取代:0001(hook 通道决策;0001 其余历史价值保留,头部已标注)

## 背景

ADR-0001(2026-11-20)否决 hook 通道,依据是 Orca v1.4.265 快照的 hook 子系统认知:2.3 万行规模、注入须写用户全局配置、随会话清理语义不成立、「净收益只剩 kimi/antigravity」。读屏三源引擎上线后暴露机制性误判(切标签快照塌缩误判 idle、打字回显误判 working,见 docs/issues/2026-11-22-session-row-spinner-and-state.md),用户拍板改走 hook、不用读屏。2026-11-23 五家 hook 能力逐家核实(调研存档 docs/agent-hooks-capability-survey.md)+ Orca hook 子系统源码复读,发现 0001 的事实基础已过时:codex/antigravity 均已推出官方 hooks;四家支持项目级注入;各家 hook 失败语义均核实为非阻塞/fail-open。

## 决策

状态证据源整体换血:agent hook 事件 + PTY 生命周期,读屏三源(标题/屏幕快照/字节环)退役。五家接入:claude/codex/antigravity/pi 项目级注入,kimi 全局注入(~/.kimi-code/config.toml marker 块——官方不提供项目级,用户 2026-11-23 明示授权的例外)。`SessionRunState` 四态枚举与渲染层零改动。

## 与 0001 顾虑的逐条对账

| 0001 顾虑 | 现状 |
|---|---|
| 子系统 2.3 万行 | 窄方案:merge 接缝 + 注入器 + loopback receiver + 转发脚本,数百行级(实测落地 agent-hooks 域 9 文件) |
| 全局侵入 | 收窄到 kimi 一家(其余四家项目级);kimi 经用户明示授权 |
| 随会话清理语义不成立 | 采纳 Orca 实践:取消该语义——启动 reconcile + 显式移除,注入是应用级事实不挂会话 |
| 净收益只剩两家 | 五家全有事件机制;antigravity 缺 waiting 事件为已知缺口(明码标价) |
| (新增)应用外影响 | env 令牌路由:应用外裸跑的会话无令牌,脚本早退零发送——从根上不存在 |

## 后果

- 状态判定不再被环境噪声欺骗(标签切换、打字回显、agent UI 改版均与 hook 事件无关);无信号 = 恒 idle,不猜、不兜底误判
- 信任门槛成为可用性边界:claude(项目信任)/codex(repo trust)/pi(project trust)未信任则静默无信号;working 失联不自动降级(hook 断则卡住,PTY 退出兜底)——v1 明码标价,实机观察后再议保险丝
- antigravity waiting 态缺失(官方无等待事件),waiting 通知对其不生效
- 读屏时代产物(安静门槛、去抖、字节环、采样 fixture)随三源退役;state:changed 契约与渲染层零改动
