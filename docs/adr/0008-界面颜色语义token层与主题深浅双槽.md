# 0008 - 界面颜色语义 token 层与主题深浅双槽

日期:2026-11-24 | 状态:已采纳

## 背景

界面颜色硬编码 Tailwind 调色板类(`zinc`/`neutral`)散布全部组件,无法整体换色。主题样式设置特性要求:8 套界面主题、深浅双槽选择。已移植的滚动条 CSS 也在引用从未定义的语义变量(`var(--foreground)` 等),一直在走兜底色。

## 决策

- 界面颜色收敛为语义 token 层(CSS 变量),组件只写语义类,不再新增硬编码调色板色。
- 主题 = 一套语义 token 值集,自带深、浅两种形态;深、浅各一个槽,设置只存选择,渲染时按当前深浅态解析套用。

## 为什么不用 硬编码继续 + 少量 CSS 覆盖

- 换主题要逐组件改颜色,8 套主题不可持续。
- 「切主题后个别界面块颜色不变」的失败形态正是硬编码漏网的直接来源。

## 为什么不用 色相式单选(一套主题深浅通吃)

- 用户拍板 Orca 式双槽:深浅两槽可完全不同,且与终端配色主题的槽机制同构。

## 后果

- 好处:换主题零组件改动;后续强调色、Match Terminal 类扩展有了地基。
- 代价:一次全组件颜色类迁移;此后新组件必须只用语义类(台账 J-002 持续约束)。
